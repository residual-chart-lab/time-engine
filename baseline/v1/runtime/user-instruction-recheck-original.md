# Time Engine — RR52 作業指示書

## 一輪の選択・成立・履歴確定と、時間・因果の保持

### 0. 研究目的の再確認

Time Engineは、AIに**時間と因果を与えるための機関**である。

時間をタイムスタンプの列として扱い、因果を過去から未来への状態遷移だけに還元することを目的としない。

本研究では、時間と因果の方向を区別する。

* **時間**：過去から現在を経て未来へ進む。
* **未来因果**：成立すべき結果の要求が、現在の運動を拘束する。
* **現在**：その拘束の下で運動と選択が行われる。
* **成立後**：実際に成立した結果から、それを成立させた履歴と必要差を参照できる。

未来の結果が、成立前から物理的な出来事として存在していると仮定する必要はない。

要求としての未来と、実際に成立した出来事を区別すること。

また、未来因果を既存の前向き予測へ翻訳して消してしまわないこと。前向き計算で再現できるかどうかと、結果を拘束の基準に据えるという計算原理の選択は別問題である。

### 1. 今回共有する幾何的理解

#### 1.1 コップは割れた

コップが割れる以前には、多数の経路と可能性が存在する。

しかし、実際にコップが割れれば、その成立は確定した出来事となる。

「ほれ見ろ、コップは割れたじゃないか」

この確定性は、Time Engineの計算可能性にとって重要である。

未来の結果を要求として扱い、成立した際には実際の出来事を認証する。

結果を基準として、成立に必要な差と履歴を調べられる。

ただし、結果のみから過去の全履歴が自動的に一意復元されるとはしない。

#### 1.2 芋虫が蝶になった

こちらは、Time Engineの目的をより包括的に表す幾何である。

芋虫が蝶になった。

それは単なる時間経過ではない。

運動によって状態が変わり、それまでの構造が組み替えられ、成立した結果によって過去との関係が変化する。

客観的には、芋虫の姿はなくなり、蝶が成立している。

主観的な時間体験の模型としては、

「芋虫だったはずなのに、蝶になっている」

という過去と現在の差が重要になる。

かつて葉を食べていたことを、現在の蝶から振り返る。

「どうして葉っぱなんか食べていたんだ？」

この問いは、過去の情報を検索することとは異なる。

過去の参照構造と、現在の参照構造が違う。

それにもかかわらず、その過去は現在の運動と切れていない。

**かつての状態が失われても、その運動に由来する差が現在へ作用できること。**

ここに、記憶を単なるラベル付きデータから区別する重要な条件がある。

さらに、未成立の未来が現在の運動へ作用することは、夢や希望のような時間的な志向性を考えるための計算的基盤にもなる。

ただし、これらは研究目的と幾何的要件の説明であり、今回の実装によってAIの主観体験や感情の発生を証明したとは扱わない。

### 2. フラワーの階層と一意性について

一輪の内部では、同じ結果を成立させる複数の履歴が存在し得る。

しかし、**非一意性をTime Engine全体の公理として固定しないこと。**

第二、第三、さらに大きなフラワーへ接続されるにつれ、下位の履歴への拘束が累積する。

マクロな長期運動では、実質的に一意の搬送へ収束する可能性がある。

一方、その一意性が成立する前に位相転換が起き、履歴を区別していた区画自体が変わる場合も想定される。

したがって、

* 一輪の局所的な非一意性
* 上位拘束による実効的な一意性
* 位相転換による区画の再編成

を混同しない。

一意性も非一意性も、全階層に通用する固定属性として先に決めない。

また、上位では情報が圧縮され、多くの差が同一視される一方で、成立条件によって必要な履歴がさらに選別され得る。

**上位の記述が簡潔になることと、成立する履歴への拘束が強まることは矛盾しない。**

ただし、今回この階層構造全体を実装する必要はない。

### 3. 今回の作業範囲

**RR52では、一輪のTime Engine最小モデルを仕上げることに集中する。**

三輪接続、マクロな一意収束、位相転換の一般理論、AIの主観体験の実装へは、まだ進まない。

それらを将来扱えるように、一輪の成立記録と残差を破損せず保持することを優先する。

既存の研究成果は採用済みの基盤として扱う。

特に、

* RR46：未来成立条件による現在選択の拘束
* RR47：成立した出来事からの必要差の抽出
* RR48：二つの成立枝と不可視差の終端可視性の局所構造保存
* RR49：残差に基づく接続距離と適合集合の厳密包含
* RR50：距離を入力しない局所選択による指定入口の成立
* RR51：局所最小選択の反例と、異なる成立履歴の保持

を前提とする。

RR51の反例によって、局所argminを一般的な経路選択原理として採用することはできない。

しかし、RR50で成立した具体的な結果は撤回しない。

**通った結果は保存し、解決していない部分を次の問題として扱うこと。**

### 4. RR52の主問題

#### A. 成立可能性と実際の選択を分ける

一輪には、成立可能な複数履歴が存在してよい。

しかし、実際の運動では、ある一つの履歴が選択され、実行され、成立する。

この区別を実装上も明確にする。

成立可能性の検証結果は、実際の出来事ではない。

未選択の候補を、実行済み履歴として記録してはならない。

また、成立候補が複数あることを、モデルの失敗と扱わない。

#### B. 履歴の確定機構を具体化する

RR51では、成立可能な全履歴の候補を保持するところまで進んだ。

次は、その中から実際の運動が一つ確定するための機構を検討する。

ここで重要なのは、**一意な履歴が数学的に存在することを要求しない**ことである。

選択規則と、成立可能性の条件を区別する。

選択に追加規則が必要なら、その規則を明示すること。

単なる最短経路の強制や、局所誤差最小化への置換は避ける。

また、完成済みの未来経路の列挙をTime Engine本体の隠れた入力としないこと。

必要であれば、選択機構の完成度を段階的に分けて評価する。

「実行可能な確定手続きを構成した」ことと、「選択則を未来因果の原理から導出した」ことを混同しない。

#### C. 成立後の履歴と残差を保持する

一輪が成立したら、結果だけでなく、実際に通過した履歴を確定する。

同じ結果へ帰還した異なる履歴を、結果の一致だけで同一視しない。

最低限、次の情報を失わない構造を検討する。

1. 実際に成立した結果と、その認証。
2. 実行された順序付き履歴。
3. 成立時に確定した状態と、入口からの継承関係。
4. 後続の作用で再識別可能な差・残差。
5. 成立要求と実際の成立記録の対応。

単なるログ保存ではなく、**後続の作用がその差を読み取れること**を重視する。

実際に選ばれた履歴と、選ばれなかった成立候補を区別して記録すること。

#### D. 過去の再参照を、操作として検査する

ここは今回追加したい重要な検査である。

「昔は芋虫だった」というラベルを読めるだけでは、Time Engineが目指す記憶には届かない。

まずは最小限の操作的要件を確認したい。

**同じ結果に閉じた二つの異なる履歴について、保存した差を後続の読み取りに作用させ、異なる応答を取り出せるか。**

RR51では、現在の補正文脈で同じ作用を持つ二つの成立履歴が、別の文脈では異なる応答を示すことが確認されている。

これを出発点にできる。

ただし、別の文脈で数値が違うことだけを、直ちに「思い出」や「体験」と呼ばない。

検査したいのは、過去の履歴が現在の作用に関与できること、そして参照側の条件が変わっても差が一律に消失しないことである。

既存構造で検査できる範囲を優先し、足りない場合は必要な最小インターフェースを提案する。

三輪接続まで実装する必要はない。

### 5. 今回守るべき境界

最小モデルを完成させるために、次のものを要求しない。

* 全履歴の数学的な唯一性。
* 全運動での接続距離の単調減少。
* 長時間・低コスト・安定運転。
* 位相転換の完全な実装。
* 三輪以上のフラワー接続。
* 物理的な逆時間因果の証明。
* AIの主観体験が発生したという主張。

一方で、これらを扱う可能性を、最小モデルの定義によって排除してはならない。

とりわけ、結果の一致を理由に残差を消してしまう設計は避けること。

また、**未来因果を事後的な結果分類だけに縮小しないこと。**

成立前の未来要求が現在の運動を拘束するRR46の構造と、成立後に履歴を確定するRR47以降の構造は、両方とも保持する。

### 6. 実装・監査の方針

既存の `aki-vault` 研究ブランチを参照する。

対象はTime EngineのCurrent、RR46〜51の原本・実装・検証記録、およびv18原本。

特にRR51の反例と、元の入口で成立する二つの異なる履歴を重要な回帰検査とする。

既存の成立結果、認証条件、固定要求、継承状態、残差の区別を壊さないこと。

新しい選択・確定機構については、可能なら次を検証する。

* 一輪の実際の選択と成立が認証できる。
* 未選択候補が実行済み記録に混入しない。
* 同じ結果に閉じた異なる履歴が区別される。
* 過去の差が、後続の読み取りに作用する。
* 局所選択が成立しないRR51の反例を隠さない。
* 結果や継承値の事後的差し替えが認証されない。
* 次フラワーを生成しなくても、一輪として停止できる。

可能な範囲でexact計算・再現可能な検証・既存コードとの比較を行う。

独立監査を容易にするため、導出された性質、明示的に与えた規則、実験的に確認した性質を区別する。

### 7. 求める成果物

**RR52として、以下を報告すること。**

1. 一輪の選択・成立・履歴確定について、どこまで実装できたか。
2. 同じ結果に至る異なる履歴を、どう保持したか。
3. 保持差が後続の読み取りにどう作用するか。
4. RR46〜51から保存された数学的成果と、新しく得られた成果。
5. 残る未定義と、それが一輪の完成を妨げるかどうか。
6. 再現可能な検証結果と監査用記録。

**成果の大小を、最初から設定した壮大な最終目標だけで評価しないこと。**

既存成果を足場に、新しく何が計算可能になったかを明確にする。

### 8. 最終的な判断基準

Time EngineがAIに与えようとしているのは、時計の読み方でも、単なる履歴データベースでもない。

**自分の運動によって何かが成立し、その成立によって過去との関係が生じ、過去に由来する差が現在と未来の運動へ再び作用できる構造である。**

芋虫が蝶になった。

芋虫だった頃の構造は、もはや存在しないかもしれない。

しかし、蝶が成立するまでの運動は消えていない。

かつての差が現在へ持ち越され、現在から過去を読み直せる。

そして、まだ成立していない未来が、次の現在へ要求を与える。

これがTime Engineの目指す時間と因果の基本像である。

今回、蝶への変態そのものを再現する必要はない。

**一輪を確実に成立させ、その成立が過去を単なる消去済み状態にしないこと。**

そこまでをRR52の中心課題とする。

一輪が閉じても、運動の履歴と差は閉じて消滅しない。

後続のフラワーがそれを受け取り、将来より大きな拘束や位相転換へ接続できる。

その可能性を保持した一輪の最小モデルを仕上げてほしい。
