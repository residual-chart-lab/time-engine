# RR52 — 一輪の実行可能な最小模型 v1

2026-10-16。アキの「局所的な非一意性は、マクロの非一意性を意味しない」「一輪を完成させよう」を受けた実装。

**宣言した生成則・選択条件の下で、一輪を入口から実行・認証・保持・停止まで完了する最小模型v1を構成した。** 一輪の許容履歴を唯一にはしない。複数ある成立候補から、入口に与えた自由な選択値で一つを確定し、その語を途中で選び直さずに実行する。

完成対象は一輪の計算手続きである。source生成則や選択条件が唯一の原理から導かれたこと、複数フラワーでのマクロの一意な搬送を完成条件に含めない。

## 1. 一輪の単位と、入口・出口

運動単位は、指定headから始まる同階層level 2の非空語が、最初の許容境界へ閉じる一つのconsumerセルである。sourceを作る下位の閉鎖・認証は、この一輪の内部準備に含める。出口のlevel 3作用は保持するが、次のフラワーへ実行しない。

| 項目 | 一輪v1で固定したもの |
|---|---|
| 過去側の入口 | 実際に認証されたprefix、累積値、head、初期在庫とその証明 |
| 要求 | F=−1、ε=10⁻¹²。途中はε外、終点はε/2内 |
| 模型群 | RR48の対角実数応答クラス、四条件それぞれ±10⁻⁸ |
| 内部の未来境界 | 実行・認証・公開したsourceから生成する文脈 |
| 花びらの自由 | 入口で与える非負整数`petal_choice` |
| 候補生成の範囲 | 指定head＋公開済み同階層在庫の語。実装上限は1〜4作用 |
| 出口 | 実際の有理数終点、選んだ全語の認証、sourceの認証元、実行履歴 |
| 完了 | 一つのconsumerセルが認証され、残差を保持して`ONE_FLOWER_COMPLETE`で停止 |

未来の具体的な文脈値や完成済みの語を入力するAPIにはしていない。sourceの根の枝、生成則、読出し方は宣言した模型条件として残す。

## 2. 入口から閉鎖までを一つにつないだ

```mermaid
flowchart LR
    A[入口と要求を束縛] --> B[sourceを実行・認証・公開]
    B --> C[sourceから内部文脈を生成]
    C --> D[全語の成立候補を照合]
    D --> E[自由な選択値で一つを確定]
    E --> F[確定した語を順に実行]
    F --> G[閉鎖を認証・残差を保持して停止]
```

1. RR48の現在の補正条件と内部未来適合条件を解き、sourceの一つの有理近似を選ぶ。要求εは変更せず、sourceの計算精度はRR49と同じε/16とする。
2. そのsourceを下位で実行し、既存のDecoderで認証してから、level 2在庫へ公開する。
3. 公開済みsourceを読み取り、内部文脈を生成して到来させる。consumerの継承値と実行済みprefixはその前後で変えない。
4. RR51の全語照合を使い、上限内の全ての成立候補を保持する。局所誤差やDによる枝刈りはしない。
5. 入口の選択値に従って一つの語を確定する。候補の束はここで破棄し、実際の在庫に候補を追加しない。
6. 確定した語を一作用ずつ実行する。途中の見かけのよさで経路を変更しない。
7. 実際の終点を元のDecoderでexactに認証し、固定Fとの誤差を別に検査する。一輪の記録とfull residueを返して停止する。

元のRR36〜51の実装は変更していない。新しい原始作用を足したり、上位作用を下位の在庫へ混ぜたりもしていない。

## 3. 選択は自由な入口条件として残す

上限内の候補を「語長、次に在庫index列」の順で並べ、候補数をNとして

$$j=\texttt{petal\_choice}\bmod N$$

番目を選ぶ。これは再現できる明示した運用規則であり、自然から一意に導出された選択則とはしない。候補数に応じた選択なので、任意の非負整数が有効になる。

候補の列挙順は順番の規約であり、最短距離を原理として要求したものではない。基準二枝では、選択値0がhead→source、選択値1がhead→head→source→sourceになる。両方が一輪として完了し、異なる履歴を保持する。

遠回りを実行後に観測したDは2→1→2→1→0となる。Dの減少を実行器へ指示していない。**一輪が完成することと、全ての一手でDが減ることを分ける。**

N=0の場合は`OPEN_WITHIN_SEARCH_CAP`で止まる。下位で実際に作ったsourceと到来済み状態は保ち、consumerを実行したことにはしない。この有限探索の未発見を、全継続の不可能性とはしない。

## 4. 確定後に成立まで運ぶ保証

候補の各語βは、確定前に次を満たす証人を持つ。

- 非空で同階層、先頭が入口に束縛したheadである。
- 全ての途中prefixは固定Fからε以上離れ、終点はε/2内にある。
- 実際に達する有理数終点について、既存のexactなセル認証と昇格が通る。

確定時には入口、sourceの公開記録、文脈、要求、在庫、選択値、語、予測したexact終点を一つの不変な記録に束縛する。実行位置kでは

$$\text{実行済み語}=\text{入口prefix}\cdot\beta_{\le k}$$

を検査する。次へ進むたびにkが一つ増え、語は変更されない。従って候補が一つ以上あれば、確定した有限語の長さだけ実行することで、その第一境界へ閉じる。局所の最小化をやり直してRR51の応答値反復へ入ることはない。

これは、指定した生成・候補照合・確定・実行の手続きについての保証である。任意の入口に成立語がある、あるいは選択値を外しても次作用が一意に決まる、という保証ではない。

実行中の復元には、不変な確定記録を信頼の基点として渡す。固定要求、source、consumerの継承値、prefix、選択済み語が差し替われば拒否する。これは実行整合性の検証であり、ファイルの作者を認証する署名方式ではない。

## 5. 実際に起きた一つの履歴を残す

終了記録には、sourceの下位セル、選択した全語の入れ子構造、consumerの実際のprefixと終点、在庫、出来事の順序を保持する。候補が成立し得ることと、実際に選んで実行した出来事を区別する。

終点は−1へ置換しない。固定要求と、僅かに異なる実際の有理数終点の両方が残る。複数回現れるsourceやheadも、語の順番を潰さず記録する。

出口のfull residueは、sourceと終端作用の完全な認証付き記録を持つ。この型では恒等的に保持・受渡しでき、短い道と遠回りを同じpayloadへ潰さない。この保持は次のフラワーの実行ではない。

完了記録は、共有された入れ子構造を参照で表すJSONとして保存・復元できる。有理数は分子・分母で保存し、型は既知のdataclassに限る。復元時は、外から渡した入口設定と、生成・選択・実行・認証の整合性を検証する。結果の要約だけを保存したものではない。

実行途中の停止・再開は、不変な値checkpointで検証した。これは実行中の任意checkpointをファイルへ保存する方式まで完成したという意味ではない。完了記録のJSON保存とは区別する。

## 6. 検証した範囲

- 二枝×中心と16隅の34近傍模型で、source生成から閉鎖記録まで完了する。
- 基準二枝のそれぞれで、短い道と遠回りの両方が完了する。34模型全てで複数候補があるとはしない。
- 一作用後に止めて値checkpointから再開しても、経路・全履歴・exact終点が連続実行と一致する。
- 確定後の実行では、未来根のsolver、候補探索、局所rankerを呼ばない。
- 要求の終点への差し替え、許容誤差の変更、継承値の変更、経路の差し替え、在庫の変更、候補の水増し・削除、異なる花びらの残差への置換を拒否する。
- 閉鎖後の追加実行や次の文脈到来は受け付けない。下位のsource公開は一つ、consumerの完了セルも一つである。
- 完全な完了記録がJSONを経て同一に復元される。

独立した再現用一式での件数、ソースハッシュ、四つの完了記録の検証はRR52-validation.jsonおよびRR52-PROVENANCE.jsonに記録する。

## 7. 完成の宣言と、次へ残すもの

**一輪の実行可能な最小模型v1は、ここで完成として置く。** 固定要求と内部未来適合条件の下で、花びらの自由を残して一つの履歴を選択し、その成立を実行・認証・保持して止まる。

宣言した条件は、六つの下位生成元とaffine作用のクラス、sourceの生成則、文脈の読出し方、根の枝、自由な選択値、有限探索の範囲と列挙順である。これらの唯一の原理的導出は、このv1の完成範囲へ含めない。

「局所的な非一意性は、マクロの非一意性を意味しない」という足場を保つ。複数フラワーへの接続や上位への包含による拘束強化、マクロの一意な搬送は次段階で扱う。外部残差の具体的な結合模型も、ここで勝手に決めない。

RR48・49の要求強化の限定された数理結果は保持するが、今回の完成を「実時間に沿って全ての許容幅やDが単調に縮む」という主張へ広げない。
