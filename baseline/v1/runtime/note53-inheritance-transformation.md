# RR53補足 — 接続で何を継承し、何を変換したか

2026-10-16。アキの「蛹ではすべてが消えるわけではない。保持される構造と、組み替わる構造がある」という補足を、接続の読み方へ反映する。原文は `user-clarification-original.md`。

**RR53の接続は、この区別に沿っている。前の出来事と作用資源を保持する一方、現在の参照文脈を変換し、その新しい条件から次のsourceと運動を作る。** ただし、元の構造の消去・剪定・圧縮まで伴う変態一般の実装ではない。

## 1. 継承・変換・新規生成を分ける

| 対象 | RR53での扱い | 次の運動での役割 |
|---|---|---|
| 一輪目の実際の終点 | 正確な有理数値のまま二輪目の入口へ継承 | 固定要求−1へ丸めず、二輪目の補正・未来適合の係数になる |
| producer／consumerの二本の累積値と実行済み語 | 文脈到来の前後では変えない | 二輪目の新しい作用だけを順に実行して加える |
| 一輪目の認証・出力・round・イベント | 不変な記録として保持し、二輪後にもprefixとして残す | 過去に何が成立したかと、どこから継承したかを照合する |
| 既存のlevel 2在庫・指定head・六生成library | 継承する | 利用可能な作用資源。ただし全ての在庫を今回の語が使用するわけではない |
| level 3の終端作用と入れ子の語 | 元の構造を保持する | 下位在庫へ混ぜず、接続口がその葉と順序を読む |
| 一輪目の現在文脈 | 過去の認証記録には保持。二輪目のliveな参照文脈は別の値へ置き換える | 過去の文脈を書き換えず、「今どの条件から作用を読むか」を変える |
| 終端履歴から二輪目へ送る文脈 | 順序付き読出しRを作り、Yhead+η(R−I/3)へ変換 | 保持差を二輪目の現在の成立条件へ入れる |
| 現在の補正解の直線・不可視方向 | 新しい文脈から計算し直す | 一輪目の係数をそのまま次の答えとして流用しない |
| 二輪目のsource・内部未来文脈・選択語 | 未来適合の下で新規に作り、実行・認証する | 一輪目に由来する差を含む、新しい一輪の運動になる |
| 固定要求F・許容誤差ε・積と認証の形式 | 今回は同じものを採用 | 宣言した模型条件であり、変態や階層一般の不変法則としては固定しない |

「記録として保持される」「今も利用可能である」「今回の運動で実際に使われる」は別である。RR53はこの三つを同一視しない。

## 2. 文脈は二段階で変わる

二輪目の入口自体は一輪目の `closed_engine` そのもの。その後、接続文脈が到来すると、producer／consumerのliveな文脈を双方とも新しいYcurrentへ移す。この時点では累積値も実行済み語も変わらない。

続いて下位で新sourceを実行・認証・公開する。そこから生成された内部未来文脈Yfutureへ、consumer側の文脈を移す。ここでもconsumerの累積値と実行済みprefixは保持する。producer側は、そのsourceを実際に作った文脈と認証を保つ。

従って、保持しているのは単に昔と同じ数値の状態ではない。**過去の出来事は変えず、現在の参照条件と、その条件から成立させる運動が変わる。** 二輪目の実際の実行に入ってから、累積値と語に新しい運動が加わる。

## 3. 接続口の読出しと、履歴の完全保持を混同しない

Rは、保存した入れ子の語をprimitiveな葉へ展開し、その順序付き重みでテンソルへ読む写像である。文脈のチャネルには元の入れ子構造を丸ごと渡していない。Rから任意の全履歴を復元できるとは保証しておらず、Rの一致だけで履歴を同じものにもしない。

一方、元の終端作用・順序付きの全語・認証は、Rとは別に完全な記録として保持する。今回使った二履歴ではRも異なり、その差が二輪目の文脈と新sourceへ効く。

つまり、**元の構造を保持する経路と、それを別の働きへ変換する経路が併存する。** 二輪目に渡った文脈だけを見て「全てを保持した」「全てが消えた」のどちらにも数えない。

## 4. 「蛹」との対応の範囲

今回確認できたのは、保存された構造が、新しい参照条件と新しい作用生成の中で働き直すこと。基本の生成元・在庫の型・認証形式は維持している。

旧在庫や旧構造を選択的に消すこと、保持差を必要十分な量まで圧縮すること、区画や接続の型そのものを変える位相転換は、まだ実装していない。「全ての旧構造を永遠に保存する」ことを蛹一般の条件にしたわけでもない。どの構造を失ってよく、何を残さなければ後の成立を保てないかは、別に検査する必要がある。

従って今回の補足はRR53の数値結果を取り消すものではなく、**保持・参照変換・新しい運動の生成を区別して読むための足場**になる。
