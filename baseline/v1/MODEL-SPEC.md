# 三輪接続模型 v1 — 操作仕様

この仕様はRR52〜54を統合した読み方を固定する。実装はRR54コミット`a67915066973a6bd5bf2c3d2fe06b0cede838b76`の同梱runtimeを使用する。新しい生成則や選択則は加えない。

## 1. 記号と実行資源

| 記号・対象 | 定義 |
|---|---|
| q、z | 四元数の実行値。今回の三輪の証人は実数部分で計算する |
| Y | 作用を読む文脈。証人ではtrace 1の実数対角テンソル |
| Kβ(Y) | 認証済みの入れ子の語βを、その文脈で読んだ作用。更新は左乗算q↦Kβ(Y)q |
| F、ε | 固定要求F=(−1,0,0,0)、ε=10⁻¹²。終点との差は四成分の絶対値和で測る |
| producer | 新sourceをprimitive作用から実行し、level 2作用として認証・公開する下位状態 |
| consumer | 公開されたlevel 2在庫を用いて一輪を実行し、level 3終端作用を得る状態 |
| upper receiver | 三つのlevel 3終端作用を実行してlevel 4へ閉じる別の受信口 |
| actual | 計画・候補試算と区別する、確定後に実際に実行された状態・履歴 |

producerとconsumerは別の累積値・実行済み語を持つ。level 3出力はlevel 2在庫へ混ぜない。最初の在庫は4作用、三輪のactualな新source公開は各一つ、最後のlevel 2在庫は7作用である。

## 2. 一輪の入口・内部・出口

入口は、元の認証済みエンジン、二つの実状態、在庫、指定head、library、固定要求、誤差基準、source枝、語の自由選択値を束縛する。現在補正文脈のsource解の自由度に対し、そのsourceが生成する内部未来文脈での適合を課す。二単純根の枝ごとに、許容誤差内の有理数代表を用いる。

手順は、sourceの下位実行→認証→公開→consumerへの内部文脈到来→候補照合→一語の確定→作用の順次実行→閉鎖・保持である。公開前のsourceを在庫として使わない。

候補照合は語長上限4の指定クラスで行い、headを先頭とする成立語を同階層在庫から列挙する。基準の二枝には短い語と遠回りの二候補がある。自由整数はこの順序付き候補集合の要素を選ぶ。局所argminや接続距離の減少を必須の選択則にはしない。

最終誤差はε/2未満、先行prefixはεの外という余裕を設ける。Decoderは**実際に得られた有理数終点**についてexactな第一境界セルを認証する。固定Fへの近似適合と、実際の終点のexact認証を区別する。終点をFへ丸めない。

閉鎖した一輪は完了し、次の要求を自動発行しない。source、終端の入れ子の語、元の入口、固定要求、二状態、在庫、認証、実行順を保持する。別の入口へ接続する場合には、その接続を明示する。

## 3. 接続の継承と変換

次の輪の元の入口は、直前の`closed_engine`そのもの。固定した接続則は

\[
Y_{n+1}^{\mathrm{current}}=Y_{\mathrm{head}}+\eta\bigl(R(\beta_n)-I/3\bigr),\qquad \eta=1/1024.
\]

Rは実際に保存されたlevel 3終端作用をprimitive葉へ展開し、順序付きの重みでテンソルへ読む写像である。Rから任意の全履歴が復元できるとは要求せず、元の全履歴は別に保持する。

接続文脈が到来した時点で両状態のliveな文脈を更新し、累積値・実行済み語は変えない。その後、新しい条件からsourceを生成・公開し、consumerの文脈をそのsource由来の内部未来文脈へ移す。producerの生成時の文脈と認証は残す。実際の新作用の実行時にのみ、累積値と実行履歴へ新しい運動を加える。

過去のround・event・output・stockは次の記録でもprefixとして保持する。旧構造の選択的消去・剪定・圧縮・生成元の型変更は、この版では実装していない。ηも原理から一意に導出した値ではなく、宣言した模型条件である。

## 4. 三輪の有限比較クラス

各輪で二つのsource枝の認証済み有理数代表と、語長4以内の二つの成立語を使用する。後の輪のsourceは、その直前のactualな出口に依存して新たに計算する。各段で候補数が二つであることも検査する。

局所的に成立する全経路の有限集合をPとし、|P|=4³=64とする。これは宣言した枝代表と語クラスを尽くした集合であり、全source係数・任意長の全履歴の集合ではない。`finite_family()`が元の入口から内部でPを計算する。

64候補は独立な試算である。actualな一つのエンジンの履歴へ64本を実行済みとして蓄積するものではない。

## 5. 共通上位要求と許容集合

共有する未来要求はY(x)=diag(x,1−x,0)、1/4<x<2/5、固定F、固定εである。経路pの三つの認証出力をO₁,O₂,O₃、三輪目の実際の終点をz₃(p)とすると、上位でのj作用後の誤差を

\[
E_j(p;x)=\left\|K_{O_j}(Y(x))\cdots K_{O_1}(Y(x))z_3(p)-F\right\|_1
\]

と定義する。全候補に同じx、F、εを課す一方、z₃は各候補が実際に継承する終点である。許容集合は

\[
M_x=\{p\in P:E_3(p;x)<\varepsilon/2,\ E_1(p;x)>\varepsilon,\ E_2(p;x)>\varepsilon\}.
\]

基準fixtureでx≈0.33471750060275535、|Mₓ|=1。一輪目への射影は4候補から{第一枝・短い語}になる。除外された一輪目につき全16後続を照合した最小誤差でも約0.0016817468200010424。上位のprefix誤差は約0.01858284→0.00974948→3.5433×10⁻¹⁵となる。

三つの実際のOを上位受信口で実行し、実際の最終値をexactに認証・level 4へ昇格する。三輪＋上位一輪の認証済み入れ子の語を保持する。

## 6. fixtureの生成と、実行の前後関係

`construct_test_requirement(0)`は、宣言した基準候補の終端多項式を使って、可解な共通未来文脈を構成する。根を有理区間で隔離し、非零の導関数を確認し、固定ε内の有理数代表を選ぶ。index 63は別の可解な共通条件の対照である。これは検査課題を作る明示的な工程であり、独立した未来供給原理ではない。

`select_macro(requirement, free_choice)`の入力は文脈・固定結果・誤差基準・自由整数であり、基準の経路名や完成経路の一覧は渡さない。ただしfixture構成自体が基準候補を使った事実は残す。判定は作用値で行い、履歴ラベルでは行わない。

全体の選択を`MacroCommitment`に確定した後は、各sourceと語を凍結して順に実行する。`execute_macro`は候補列挙、根解法、局所再計画を呼ばない。実際の前の出口と次の入口が一致しなければ拒否する。完了済みの一輪目を後から修正して辻褄を合わせる工程はない。

## 7. 保存・検証と停止の意味

JSONの既知型だけを許すobject graphで、厳密な分数と共有構造を保存する。巨大整数は小さな十進片で変換し、数値を浮動小数へ置き換えず、プロセス全体の整数制限も変更しない。未知の型・循環参照は拒否する。

インポートは外から渡した期待入口／未来要求と選択値に照合する。正規の選択計算をやり直して照合する段階と、その確定記録に対する実行再認証だけの段階を区別する。作者の身元を保証する暗号署名ではない。

一輪の正常完了、指定有限集合内で候補がない状態、chartや表現の不成立を区別する。有限集合内で候補がないことは、全てのTime Engine運動の不可能性を意味しない。この版は三輪と上位一輪の閉鎖で止まる。

## 8. この版で固定する不変条件

1. 固定要求・許容誤差・元の入口・継承値を、実行後に差し替えない。
2. 実際の終点を丸めず、次の補正と認証に継承する。
3. 新sourceは実行・認証・公開されてから利用する。
4. 階層の違う作用を同じ在庫へ混ぜない。
5. 確定後にsource・語を探し直さず、選んだ順序で実行する。
6. 候補試算を実際の在庫・過去の出来事に混ぜない。
7. 同じ要求を満たした異なる履歴を、同じ終点ラベルへ潰さない。
8. 接続で過去の累積値・実行済み語・認証・在庫をリセットしない。
9. liveな文脈の変換と、過去の認証内の文脈の保持を分ける。
10. 共通上位要求を、実際の一輪目の実行前に束縛する。
11. 上位作用にも、三つの下位の入れ子の履歴を保持する。
12. 有限模型内の条件付き一意性と、全階層での一意性を分ける。
