# RR66 — 要求に応じて同一性の解像度を選び、同じ履歴で切り替える

2026-10-22。RR65固定版 `6d3a949f3cca69f3e0be9a3b1457cc306296b374` からの追加。

**RR65で積だけでは扱えなかった非零結合を、積と、実際の接続で使う重み付き和で扱えた。** 個別のs,tをすべて開く前に、その要求に十分な中間の読出しがある。

今回は、要求から十分な観測を証明して選ぶ処理と、同じ保持記録の上でその選択を変更する実行器を加えた。変更は実行前の要求更新として時系列に記録する。現在がvと語を選び、要求と選択を確定してから、実際の二輪と上位セルを閉じて停止する。

## 1. 四つの観測

元のs,tと、RR65のp=stはそのまま残す。追加するのは、同じ元値に由来する次の観測である。

\[
u=s+t,\qquad w_{word}=a_{word}s+b_{word}t.
\]

a,bは成功例から調整しない。既存RR53で読まれるprimitive葉の位置から求める。

- `HHHSUT`は9葉に展開され、Sは7番、Uは8番。w=7s+8t。
- `HHHUST`ではSが8番、Uが7番。w=8s+7t。
- RR53の分母は45。Tの9vと固定部分は既知の係数として残す。

選べる観測は、定数判定、p、(p,u)、(p,w)、(s,t)。既存のguardと、新しいT/Rの全係数をこれらで厳密に表せるかを順に検査する。αだけの一致では済ませない。

| 要求・接続の例 | 証明できた観測 |
|---|---|
| RR65の混合C、結合0 | p |
| 同じ混合C、結合1/1024 | pと、その語のw |
| mainのC、結合0 | pとu |
| mainのC、結合1/1024 | 今回のカタログではs,t |
| 非零結果へ届かない既知のケース | 定数の不成立判定 |
| 認証chart外 | 未解決。省略許可にはしない |

これは観測の数だけによる一本道ではない。(p,u)と(p,w)は一般には比較できない別の分け方である。どちらもpだけより細かいが、個別のs,tを一意に定めるとは限らない。

例えば(p,w)は、a,bが非零なら

\[
(s,t)\longmapsto ((b/a)t,(a/b)s)
\]

という別の組も同じ値へ写す。この範囲では、それでも同じT/Rとguardを再現できる。**保持履歴を同一視したのではなく、指定した作用観測Pについて必要な区別を選んでいる。**

## 2. 推測ではなく、多項式の恒等式で確かめる

RR65の13個の作用・guard多項式を自由数runtimeから受け取る。pのみなら、全単項式がs^n t^nへ相殺・整理されるかを調べる。

(p,z)、z=as+btの場合は、

\[
t=(z-as)/b,\qquad s^2=(zs-bp)/a
\]

を用い、各多項式を

\[
f(s,t)=A(p,z)+sB(p,z)
\]

へ厳密に還元する。Bが0になる場合だけ、その多項式を(p,z)で扱えると認める。残った項を小さいからと捨てない。

さらに、採用する式へp=st、z=as+btを再代入し、**元の多項式の全係数と一致することを別に確認する。** 数点で一致したから採用する処理ではない。

必要な全式が通った観測だけを採用する。資源区間・分母・正則性・初回境界・sourceの活動性は、選んだ観測から既存の判定で確認する。

有限カタログの指定順で、証明できた十分な観測を選ぶ。任意の関数や全ての有理式の相殺まで探索した、普遍的な最小情報量の定理ではない。観測予算で必要な候補を使えなければ、数学的な不成立と混ぜず未解決にする。

## 3. 読んだ情報は失わず、新しく必要な分だけ読む

派生観測u,wは登録時に厳密に計算・認証する有限のカタログである。その初期費用と保持量は省略していない。元のs,t,pのVaultを変更せず、追加観測は別のVaultへ保存する。

要求更新後も、既に読んだ正確な観測とその由来はキャッシュに残す。別の要求の判定証や作用は使い回さず、**値と由来を再利用して、新しい要求について証明し直す。**

同じ入口から、次の順で要求を更新した。

| 順番 | 採用観測 | 新しくVaultから読んだ値 | 既存の観測から復元した値 |
|---:|---|---|---|
| 1 | p | p | — |
| 2 | p,w | w | — |
| 3 | p,u | u | — |
| 4 | s,t | なし | s,t |
| 5 | p | なし | — |

4では、既にuとwがある。a≠bなので、

\[
s=(bu-w)/(b-a),\qquad t=(w-au)/(b-a)
\]

から一意に復元できる。元値のcommitmentにも照合し、再読出しと復元を別に記録する。

一方、pと一つのwだけでは一般に二つの枝が残る。その状態から個別値の観測へ移る試験では、枝を勝手に選ばず、元のs,tを読む。二つの語のwが両方読まれていれば、それらの連立式からも一意に復元できる。

最後にpへ戻っても、細かいキャッシュや元記録は消さない。変わるのはその要求の評価で使う観測であり、過去に読んだことを忘れた扱いにはしない。

## 4. 要求更新も実際のTE履歴に入れる

段階は次の通り。

```text
要求を束縛 BOUND
    ↓ 現在がvと語を選ぶ
CHOSEN
    ↓ 観測を選んで、必要な値だけ精査する
READY または BLOCKED
    ↓ 要求・選択・観測証を確定して実行
二輪と上位セルが閉じて STOPPED
```

実行前なら、明示した新しい要求へ更新できる。更新すると古い選択と作用を無効化し、元値とキャッシュを保持したままBOUNDへ戻る。語を選び直した場合も、以前の作用では実行できない。

各更新・選択・読出し・実行確定のdigestを、元のTEのイベント時系列へ追加する。その履歴を含む同じ在庫・下位累積値から、TとRを実際に生成・認証・公開する。第一輪の実際の出口文脈と、選んだ観測による予測が厳密に一致することも確認する。

**(p,w)で通る接続では、精査と実行直前の照合の両方について、元のs,tへの厳密読出しを禁止しても実行できた。** 照合だけ裏で個別読出しへ戻す経路は使わない。

実際に保持されているsource作用、下位生成、Decoderは引き続き既存の厳密演算を使う。Vaultからの個別値の再抽出を省くことと、実行中の全ての有理数演算を低精度にしたことは別である。全体の高速化率は計測していない。

実行開始時の要求と現在選択は固定する。完了後の要求変更や自動的な次輪の開始は受け付けない。今回の二輪の途中に新しい要求を差し込む段階実行は追加していない。

## 5. 保存と再開

要求更新の列、選択、採用観測、新規読出しと復元の区別、元の数のアーカイブ、追加観測のアーカイブ、実際の在庫・時系列・成立記録を保存する。

読込には外部で保持したSHA-256と、認証済みの元の入口・初期要求を必要とする。現在要求と選択を外から指定して照合することもできる。既知のコマンドだけを順に再実行し、観測証・キャッシュ・TEの実状態を照合する。

保存済みの値は、由来と値のcommitmentへ再照合する。digestだけを借りた別の継承値、別入口のキャッシュ、要求更新前の作用、実行後に追記した要求変更を拒否する。観測の整数・有理数表現は自由数runtimeのchunk整数codecを使い、環境の十進桁数上限へ依存しない。

要求履歴の上限は100コマンド、保存データは20MB。今回の完了記録は元の二つの過去の閉鎖と、要求更新後に実行した二輪を保持する。在庫は6→7→8、round数は2→3→4。履歴をリセットして再実行を成立扱いにしてはいない。

## 6. 検証結果

主入力は[事前コミット1b1fa6c](https://github.com/residual-chart-lab/time-engine/commit/1b1fa6c76acdbaa39e6adb2f557b7bad588e794d)で固定した。SHA-256は `d2b69bec39636bab6cbe277481021597dde2b7c0768dd0ff924f60ad995d09d7`。

- 4文脈×2接続強度×4現在係数×2語の64計画が、別の厳密行列・補正計算と一致。
- 採用計画はpが6、(p,w)が6、(p,u)が8、個別値が8、定数の不成立・未解決が36。定数の36件では厳密な観測読出しは0回。
- 計画選択は値を読む前に行い、完成未来経路を作らない。非零結合でも(p,w)の同値性は多項式恒等式で保証する。
- 事前指定した5つの要求更新列で、実際の二輪と上位セルが成立した。保持・消去を含む入口、復元、語の変更、粗い観測へ戻る場合を含む。
- 積から接続読出しへ進む列では、新しく読むのはpの後にwだけ。元のs,tの厳密読出しはない。
- 7つの保存時点で、再開後の状態digestと、その後の実際の運動を再現した。
- 観測予算1で(p,w)を要求すると、未解決として停止する。原モデルの不成立と誤記せず、許可なしで個別値を開かない。

検査件数とハッシュは [RR66-validation.json](../integrations/inquiry/RR66-validation.json)。新しい結果は`.work/rr66-local/`へ出力し、旧版の結果を変更しない。案内文書2件以外のRR65基準311ファイルを照合する。

## 7. 動かす

Python 3.10以降、標準ライブラリのみ。まず二つの要求を同じ入口で扱う実演：

```sh
python run_adaptive.py demo --out-dir .work/adaptive-demo
```

七つの段階記録とmanifestを新しいディレクトリへ保存する。最終段階は二輪と上位セルが閉じたSTOPPED。既存ディレクトリを上書きしない。

一段ずつ動かす場合：

```sh
python run_adaptive.py start --context mixed --strength 0 --out .work/start.json
python run_adaptive.py choose --record .work/start.json --sha256 <返された値> --v 1 --word HHHSUT --out .work/chosen.json
python run_adaptive.py resolve --record .work/chosen.json --sha256 <返された値> --out .work/resolved.json
python run_adaptive.py revise --record .work/resolved.json --sha256 <返された値> --context mixed --strength 1/1024 --out .work/revised.json
```

更新後は再び`choose`、`resolve`を行い、最後に`execute`で動かす。`verify`は外部で保持したハッシュと記録を使って照合する。mixed・強度0以外から始めた場合は、読込時に`--initial-context`と`--initial-strength`で元の初期要求を指定する。

```sh
python integrations/inquiry/validate_adaptive.py
```

観測候補は今回の有限カタログと既存RR53に依存する。未知の模型で最小の観測を自律発見する機構や、自律的なC生成までは導出していない。ここで確定したのは、**同じ保持を失わず、要求に十分な同一性の解像度を証明して選び、その切り替えを実際の運動へつなぐ処理**である。
