# RR62 — 未来要求から、保持差への精査と現在の実作用をつなぐ

2026-10-20。完成した3+1とRR58〜61を使い、Time Engineの結合則を強化する。

**同じ未来要求でも、成立可否だけを知る問いでは保持差の厳密値を読まずに済み、実際の補正を決める問いではその差が必要になる。今回は元の保持sourceを実際の語に再使用し、保持差によって新しく生成するsource自体も変わるところまで接続した。元の履歴や差は消去しない。**

## 1. 固定した入力と今回の変更

[RR61](RR61_INDEPENDENT_C_PULLBACK.md)は、独立Cから現在の補正を計算し、前向き到達可能性との等価性を示した。ただしRR61の相対補正uでは、\(u=K(C)-s\)を代入すると新sourceの係数は\(\lambda_*+K(C)\delta\)になる。保持差は必要な相対補正を変えたが、補正後のsource作用そのものは共通になった。この違いを今回の出発点とする。

RR62では、元の保持source Sを実際の語に残し、新しい補正source Tと組み合わせる。Sは既に同階層の在庫にあり、Tは既存の下位実行・認証・公開を経て作る。新しい種類の原始作用やDecoderを追加しない。

[入力JSON](../integrations/inquiry/RR62-inputs.json)は、結果の計算前に[5cace658](https://github.com/residual-chart-lab/time-engine/commit/5cace65874ef7334154b1b7e51bf77b04ba3b8ed)へ固定した。SHA-256は`5aea8291c577aa257e7a795ca8ba7b168bb1c17cee67256dfef0703bfc8d4e1f`。

- RR61の独立境界14点を、成功・失敗を選別せず全て再使用。\(Y_C=\operatorname{diag}(x,1-x,0)\)、\(x=k/4\), \(k=-4,\ldots,8\) と \(x=1/3\)。今回の新しい独立標本とは数えない。
- 未来要求+1、実際の現在からの継承値−1、現在のY0、head Hは固定。
- 保持・消去・復元の接触01・gain 1の三履歴。
- 補正vの許容区間は\([-64,64]\)と\([0,4]\)。成功経路から区間を逆算しない。
- 問いPは「認証可能な現在補正が存在するか」と「許容される現在作用の集合」の二種類。
- 現在の語は`HHST`と`HHTS`。Hは現在応答−1/9、SとTは−9。どちらも最初の非空終端で−1へ閉じる。
- 保持差の認証済み粗範囲は\(s\in[-1/1024,1/1024]\)。入口で実際のexact値をこの範囲へ照合し、範囲外の入力は拒否する。

三履歴×14境界×二区間が84接続課題。それぞれに二種類のPを与え、計168件を判定する。

## 2. 保持差が実際の新sourceを変える作用則

元のSの係数は\(\lambda_*+s\delta\)、新Tは\(\lambda_*+v\delta\)。現在では不可視な方向\(\delta=(-2,1,1,0,0,0)\)を、RR61の幾何から得る。元のSを新Tで上書きしない。

未来境界Cで

\[
h=H(Y_C),\quad a=S_*(Y_C),\quad g=\delta S(Y_C),
\qquad A_s=a+sg
\]

とする。全て実スカラーの宣言クラスであり、hとgは今回それぞれ\(-(2x-1)^2\)、\(2-6x\)。二つの現在語はどちらも、未来側で実際の現在終点へ作用して

\[
q_C=-h^2(a+sg)(a+vg)
\]

を与える。したがって、\(hgA_s\ne0\)なら、+1を満たす補正は一意に

\[
\boxed{v_C(s)=\frac{-1/[h^2(a+sg)]-a}{g}}
\]

となる。宣言区間内で、既存のregularな認証チャートにあることも必要である。完成経路の列挙は使わない。Cは二つの語の順序を選ばない。

### 必要性と十分性

極\(a+sg=0\)をまたがない範囲では

\[
\frac{dv_C}{ds}=\frac1{h^2(a+sg)^2}>0.
\]

よって、同じC・同じ粗範囲・同じ現在応答でも、異なるsは異なるvを必要とする。二点間でも

\[
v_C(s_2)-v_C(s_1)
=\frac{s_2-s_1}{h^2(a+s_1g)(a+s_2g)}.
\]

両方の補正が許容区間内にあるなら、許容作用集合は異なる。代表値と粗範囲だけから、全てのsについて正しい補正値を一つ返すことはできない。必要なのはsまたはそれを識別する同等の情報であり、特定の変数名やメモリアクセス方式の不可避性を主張しているのではない。

逆に、sとCを与えれば上式で補正を計算し、新Tの下位実行・認証・公開、現在語の実行、上位認証まで進められる。この宣言した二語・一区間内の補正について必要十分である。任意の在庫・任意の語に対する一般的必要十分性には広げない。

最初のC、x=−1では、消去時v≈3.374947416484086、保持時v≈3.374947416705408。差は約\(2.21\times10^{-10}\)だが、新Tの係数と未来kernelはexactに異なる。現在のkernelはどちらも−9である。小さな係数差を、大きさだけで捨てる処理にはできない。

## 3. Cだけでなく、何を知りたいかPを束縛する

同じCでも、**存在を知ることと、実行する作用を特定することは別の観測**である。スコープには認証済み入口・C・補正区間・P・語族を含める。判定証のスコープが変われば拒否する。

入口のexact認証から、粗い区間\(I=[s_-,s_+]\)だけを読出し段階へ渡す。元のS、係数、保持差、履歴はArchiveに残る。

極を含まないIでは補正則が厳密に増加するため、補正の可能範囲は

\[
J_C(I)=[v_C(s_-),v_C(s_+)]
\]

として二端点から求まる。

| 課題・条件 | 判定と精査 |
|---|---|
| Pが存在、J全体が許容区間内 | 全てのsで成立可能。exactなsの読出しを省略 |
| Jと許容区間が交わらない | この範囲では空。exactなsの読出しを省略 |
| Pが作用集合、成立候補が残る | sを精査し、実行できる具体的なvを求める |
| 存在の境界をJがまたぐ | 未判定から精査へ。勝手に代表値で判定しない |
| Iがsourceの極を含む | 安全な省略保証を出さず、精査へ回す |
| 認証チャート外 | 認証可能性は未対応として保持。全体的不成立とはしない |

h=0ならこの語族の未来応答は0。g=0なら\(-h^2a^2\le0\)なので+1にはならない。この二つは具体的な不成立条件として、sを読まずに返せる。

存在の判定証はvを含まず、source公開や実行の許可には使えない。作用集合を要求したスコープの解決へ進み、必要な保持差を読んでから具体的な補正を実行する。未判定を置換可能と扱わず、差の消去を許可しない。

## 4. 一続きの実装と結果

処理は以下の順で行う。

1. 完了した実際の履歴を認証し、粗範囲と元の記録をArchiveへ保持する。
2. CとPから、差の精査が必要かを判定する。
3. 全168判定を[実行前の記録](../integrations/inquiry/RR62-starts.json)へ保存する。
4. 省略できる問いは粗範囲で答え、必要な問いだけexactなsを読む。
5. 具体的なTを下位で実行・認証し、同階層の在庫へ公開する。
6. 現在が選んだ語で、元のSと新しいTを実際に使って閉じる。
7. 認証済みlevel 3出力と実終点−1を上位へ渡し、Cの+1をlevel 4で認証する。

[結果JSON](../integrations/inquiry/RR62-result.json)には全168件と実行記録を保存する。

| 問いP | 件数 | 真／偽／認証範囲外 | 解決段階のexactなsの読出し |
|---|---:|---|---:|
| 補正が存在するか | 84 | 48／24／12 | 0 |
| 許容される現在作用の集合 | 84 | 48／24／12 | 48 |

全168件が、元の保持sourceの未来応答を直接exact計算する対照と一致した。フィルターの判定・解決段階では、差を持つ元sourceの未来応答の追加展開を行わず、必要な48件で保持スカラーsを読む。

**この読出し件数は判定・解決段階だけの計測。** 入口のexactな認証と範囲照合、代表sourceとheadの計算、ハッシュ、実際のsource生成・公開、実行時のexact再照合、結果確認用oracleは別に必要である。処理全体の精度削減率や高速化率、保存量削減とは数えない。今回、情報が不要になったことと、値の展開を省いたことを混同しない。

広い補正区間で許容された30件を`HHST`で実行し、全件exactに未来+1へ閉じた。最初の固定Cで三履歴それぞれに`HHTS`も実行し、成功認証は計33件。保持時と消去時で、新Tの実際の係数・未来kernelが異なることも照合した。

消去時の補正を保持時へ流用する一対照では、元の保持Sと、その値で合法に生成・公開したTを使う。現在は−1へ閉じるが、未来誤差はexactに

\[
q_C-1=\frac{sg}{a}\ne0
\]

となり、+1の認証を得ない。計34実行、33成功であり、この対照を成功へ混ぜない。

## 5. 同じ成立結果でも、次の読出しには順序差が残る

`HHST`と`HHTS`は、今回の現在結果とCの未来結果について置換可能である。一方、閉鎖した実際のlevel 3出力に既存RR53の順序付き読出しRを適用すると

\[
R(\mathrm{HHST})-R(\mathrm{HHTS})
=\frac{X_T-X_S}{21}\ne0.
\]

Hは二つのprimitive leaf、SとTは一つずつなので、全六leafの最後の二位置5・6が交換され、分母は\(6\times7/2=21\)となる。未来+1を満たすには\(h^2A_s(a+vg)=-1\)なので、実数のSとTの未来応答は異符号であり、テンソルも同一にはできない。これは全ての成立した宣言語対で差が残る理由になる。実装では保持時の一対をexact照合した。

局所的な成功の一致は、次の接続読出しまで同じであることを意味しない。今回は次の輪を実行したとは数えず、既存の接続読出しに差が渡るところまでを確認する。差を消さず、次のスコープに新しい保証を求める原則を保つ。

## 6. 採用範囲と前向き対照

今回強化したのは、**C・読出し目的P → 必要な保持差の精査 → 現在の具体的作用 → 実行・閉鎖**という結合である。必要性は補正則の厳密な依存性から、十分性はその解の実行と認証から支える。存在の問いに不要な精査を実行の問いへ流用しない。

同情報の前向き模型にも同じ機構を実装できる。前向きには、固定sの下で\(-h^2(a+sg)(a+vg)\)をvについてaffineに伝播し、+1の原像を取れば上式を得る。sを区間に保てば同じ条件付き区間判定になる。この宣言クラスでTE固有の計算原理が追加証明されたとはしない。RR61の等価性の留保を維持する。

固定head、現在Y0、対角C、既知の一方向の残差族、Tの生成族、二語、補正区間、Pの指定は模型条件である。任意の履歴差の自動発見、Cそのものの内生生成、多方向の注意、全TEの精度配分は今回の完成範囲には含めない。
