# RR67 — 未来要求の変更から、計算し直す範囲を取り出す

2026-10-23。RR66補修版`62904368873f3383246d64a71281be1ae7746b96`への追加。

**要求が変わっても、変わらない関係の保証は再利用できる。ただし、現在の要求に対する成立判定は、その要求へ新しく結び直す。** RR67は、この区別を実行可能にする。

RR66は既読の値を保持し、要求に十分な観測を選び直せた。RR67では、その観測を証明する計算と、補正作用を組み立てる計算にも範囲を持たせる。未来文脈C、接続強度、補正の許容範囲、現在の語・係数、観測予算の変更について、影響する部分を計算し直す。

## 1. 比較の単位

同じ認証済み入口、同じ保持差s,t、同じ二輪の要求、同じ現在選択を使う。

- 全計算の対照：元のRR65/RR66の式を作り直し、観測を選び、作用を求める。RR66の計画キャッシュとRR65のrecipeキャッシュは、比較の各時点で消す。
- RR67：元の13式を固定した算術グラフへ展開し、入力の投影が一致する段階だけを再利用する。観測への因数分解と区間包含も、保証の入力が一致する場合に再利用する。

対照のキャッシュを消すのは計算方法の比較であり、実行履歴や保持値を消す操作ではない。どちらも元の在庫・累積値から実行する。二輪が閉じると停止する。

入口に必要な登録費用、数学的な適用範囲、精査に必要な値は同じ。完成した未来経路を作ってから、現在の再計算箇所を決める処理は使わない。

## 2. 対角作用から同じ13式を作る

既存の認証済みsource族を

\[
S_i=x_i+d_i s,\quad U_i=x_i+e_i t,\quad T_i=x_i+d_i v
\]

として扱う。x,d,eとheadの対角成分は、入口で認証された代表と作用基底から取り出す。元のs,tの正確な値は読まない。

trace 1の対角テンソルXと未来文脈Cについて、既存のkernel読出しは

\[
K_C(X)=2\sum_i c_i X_i-1
\]

となる。既存headのkernel、実際の語のprimitive葉の順序・位置重み、RR53の接続式を用い、RR65と同じY、head応答、第一語応答、補正の分子・分母、Rの三係数を作る。

RR65の13出力に加え、sourceや中間式の段階を明示する。非零接続では32段階、接続強度0では29段階。0倍によって消えるraw文脈への依存は、厳密な恒等式として除く。微小だから省く処理ではない。

このグラフは既存の式から設計した固定スキーマである。新しい作用則や依存関係そのものが運動から自律生成された、とはしない。対象はRR65/RR66の対角source族、二つの語、二つの接続強度、既存の固定結果・継承値・作用観測である。

## 3. 再利用を許す条件

### 算術の段階

各段階nについて、操作、固定パラメータ、親の完全な多項式係数をまとめた投影をπₙとする。元の入口と算術スキーマも束縛する。

\[
\pi_n(q)=\pi_n(q')\quad\Longrightarrow\quad f_n(q)=f_n(q').
\]

証明はグラフの順序に沿う帰納法でよい。固定値の段階では投影が値を指定する。後続の段階では、同じ操作へ同じ完全な引数を渡すので同じ多項式になる。親が再計算されても、相殺後の完全な多項式が同じなら、その後の段階は再利用できる。

これは再利用の十分条件である。異なる引数でも結果が相殺して同じになる全ての場合を、計算前に発見する必要十分条件や、普遍的な最小再計算の定理ではない。

### 観測の同一性証明

因数分解の保証は、完全な元多項式f、観測の定義φ、代数スキーマへ結びつける。

\[
f(s,t)=\widehat f(\phi(s,t)).
\]

新規の保証を作るときは、RR66と同じ厳密な因数分解を行い、元変数へ再展開して全係数を照合する。fとφが同じなら、その恒等式は別の要求でも有効である。新しい要求の全ての式について利用可能性を確認し、要求・現在選択・観測予算を束縛した新しい計画を発行する。

`7s+8t`と`8s+7t`は別の観測定義である。名前や観測数が似ているだけで同じ保証として扱わない。拒否された因数分解の結果も、同じ完全な入力の場合にだけ再利用する。

### 区間包含と成立判定

区間包含は、完全な多項式と、その多項式に現れる全変数の現在の区間が同じ場合に再利用できる。粗い区間から正確な値へ移った場合、変化した区間を古い包含へすり替えない。

一方、headの非零性、chart、初回境界、補正の許容範囲、分母などの合否は、**現在のCと資源範囲に対して改めて判定する。** 同じ作用式が使えることは、同じ許可が有効であることを意味しない。

ハッシュはキャッシュの索引に使い、再利用時には入力投影そのものも厳密に照合する。キャッシュの証明・包含は凍結した値として発行し、同じ形の未発行コピーを拒否する。これは既存実装と同じ、信頼したプロセス内の入口・発行器を使う模型であり、第三者の未検証な証明書を受理する仕組みではない。

## 4. 変更の種類で、起こす範囲が変わる

| 変更 | 再利用できた部分 | 改めて必要になる処理 |
|---|---|---|
| 未来文脈Cのみ | source族、現在T、接続文脈Yとその局所headなど | Cへの応答、補正の引戻し、影響した観測証明、現在の合否 |
| 接続強度0→1/1024 | source族など | raw文脈、Y、その影響先、必要な新観測 |
| 補正の範囲のみ | 全ての作用式とその包含 | 新しい範囲での合否 |
| 現在の語 | 語によらないsource族など | 順序付き文脈と語別の観測 |
| 観測予算のみ | 算術と既存の観測恒等式 | その予算で観測を使えるか |
| 以前と完全に同じ要求・選択 | 発行済み計画 | 既存の計画キャッシュを利用 |

最後の完全一致のキャッシュはRR66にもある。今回の主対象は、**まだ計画を作っていない別の要求への移行**である。

非零接続でmixedのCからmainのCへ移る比較では、32段階中18段階を再利用し14段階を再計算する。補正範囲だけを狭める比較では32段階全てを再利用できるが、許容候補は成立可能から不成立へ変わる。

因数分解や包含の再利用件数には、一つの計画内で同じ式を共有した場合も含む。作業記録には再利用したmodeと出力名を残し、全件を別要求からの新しい移植成功とは数えない。

## 5. 値の精査と実行

算術や証明の再利用と、保持値のキャッシュは別に扱う。RR66補修版の規則を用い、p、和、語別の重み付き和、個別値を必要な分だけ読む。p,wから個別値が必要になれば、sを読み、tを関係から導いてcommitmentへ照合できる。元のs,tと全ての観測は保持する。

要求更新時には古い準備済み作用を失効させ、現在がvと語を選び直す。要求・選択・観測証を確定してから、既存の生成・認証・公開・Decoderで二輪と上位セルを閉じる。在庫は6→7→8。元の累積値と過去の閉鎖は継承する。

詳細な作業記録は、計画時にどの段階・証明・包含を作成または再利用したかを示す。TEの時系列には要求更新・現在選択・精査・実行確定が残る。キャッシュが温まったかどうかは運用上の費用であり、数学的な計画のdigestには含めない。保存再開では同じ数学的な計画と実運動を再現し、再利用件数そのものの一致は要求しない。

RR67の記録には専用のschemaと実行器を使う。再開時は、外部で保持したSHA-256、認証済みの入口、元の初期要求を照合し、数の完全アーカイブとコマンド・実運動を再検証する。別の入口へ読替える許可ではない。

## 7. 動かす

Python 3.10以降、標準ライブラリのみ。リポジトリのルートで：

```sh
python run_incremental.py demo --out-dir .work/incremental-demo
python integrations/inquiry/validate_incremental.py
```

実演は要求更新列を一段ずつ保存し、最後に二輪と上位セルが閉じたSTOPPEDで終わる。既存の出力ディレクトリを上書きしない。`start`、`choose`、`resolve`、`revise`、`execute`、`verify`でも操作できる。

```sh
python run_incremental.py start --context mixed --strength 0 --out .work/rr67-start.json
python run_incremental.py choose --record .work/rr67-start.json --sha256 <外部で保持した値> --v 1 --word HHHSUT --out .work/rr67-chosen.json
python run_incremental.py resolve --record .work/rr67-chosen.json --sha256 <外部で保持した値> --out .work/rr67-ready.json
python run_incremental.py revise --record .work/rr67-ready.json --sha256 <外部で保持した値> --context main --strength 1/1024 --domain zero --out .work/rr67-revised.json
```

更新後は再び選択・精査する。初期要求がmixed・強度0・wide以外なら、読込時に`--initial-context`、`--initial-strength`、`--initial-domain`を指定する。元の保持条件も同じものを指定する。観測予算・補正範囲を省略した要求更新では、それまでの指定を保つ。

**未来要求が変わったとき、その変更が必要にする計算を、現在の実行に先立って取り出す。** 今回増やすのは、そのための範囲付きの保証である。
