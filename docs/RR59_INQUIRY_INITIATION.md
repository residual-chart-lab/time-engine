# RR59 — 棘の精査：どこから調べ始めるか

2026-10-18。RR58の次に、**保持した差から精査の起点を拾うこと**と、**拾った差が指定した仕事に効くかを確かめること**を分ける。完成した3+1と、TEの実行・認証・履歴は変更しない。

## 1. 出発点となった出来事

アキは、Workの長い作業報告を概観していたとき、次の一行に引っかかったと報告した。

> 3+1が作る係数の差を丸めず、有理数のまま後続へ通しているため、この照合に少し時間がかかっている。

アキは作業の速さを要求していたのではない。進捗を伝える目的には不要だった一行が、保持する差と実際に精密演算する差を分ける問いへつながった。アキは、Workが計算中の引っかかりを外へ差し出した事例として、これを「棘」と判断した。

この機能的な事例を研究対象として採用する。意図や自己認識を成立条件には置かない。一方、記録はユーザーが提示した作業報告と読取りの申告であり、生成直前の内部活性、逡巡の長さ、予測誤差の値は測定していない。

今回観測された連鎖は、**Workが一点を出す → アキが拾う → 精査が始まる**。Work側での候補の出現と、人間側での選択を別々に記録する。LLM単独で同じ研究方向を自動的に選べたという実験には数えない。報告の慣習でその一行が生じた可能性も、機能的な連鎖を無かったことにはしないが、内部機構の同定には対照が要る。

アキの「予測符号化」という説明は、この調査の原理仮説として保持する。RR59は生物の機構やLLM内部の同一機構を立証する試験ではない。

## 2. 精査で固定する区別

**棘は精査の起点になり得るが、その時点で重要性の証明を持つ必要はない。**

発火時点で使った情報と、選ばれた行為を先に記録する。その後で、何が変わったか、要求の成立に効いたか、どの範囲で不要だったかを検査する。後で重要と分かった差を、最初から検出できていたと書き換えない。

| 段階 | 問い | 記録するもの |
|---|---|---|
| 保持 | 後で読み直せるか | 元の差、運ばれ方、認証元 |
| 起点 | いま何を調べるか | その時点で利用した観測、発火・非発火、対象 |
| 精査 | 指定した仕事に効くか | 保存対象P、境界、要求、対照、結果 |
| 認証 | 実際の出来事として成立したか | 既存の入口・在庫・階層・終点・履歴 |

非発火は、差を消す許可にも、全ての未来で無関係という証明にもならない。発火も、候補やsourceを実在庫へ公開する許可にはならない。[RR58の基本原則](PRINCIPLES.md)を保つ。

## 3. 現在の圧縮値だけを見る検出器の限界

RR58の四sourceについて、次の指定した現在の読み取りを考える。

\[
\Phi(X)=\bigl(m_2(X),K_X(Y_{\rm current})\bigr).
\]

四候補のΦは同じ。しかし、到来した別文脈で代表sourceと作用値が異なるかというラベルは、`false, true, true, true`に分かれる。

**補題。** Φ(a)=Φ(b)で、調べたいラベルL(a)≠L(b)なら、Φだけを入力とする決定的な検出器Tは、両者を正しく選び分けられない。

証明はT(Φ(a))=T(Φ(b))で終わる。同じ入力に同じ分布を返す確率的検出器にも、両者を確率1で正しく識別することはできない。

これはTEの現在に情報が存在しないという命題ではない。元の係数、残差、履歴は現在にも保持されている。**指定した圧縮読取りだけに検出を閉じ込めると、起点を選び分ける情報が足りない**という限定した主張である。全候補を警戒して調べることはできるが、この読み取りだけで選別できたことにはならない。

## 4. 一つの手がかりを試す

RR58の既知の一方向の族

\[
\lambda=\lambda_*+s\delta,\qquad
K_\lambda(Y)-K_{\lambda_*}(Y)=sG(Y),\qquad
G(Y)=\sum_k\delta_k K_k(Y)
\]

を使う。今回宣言した起点規則は、**到来したYでs≠0かつG(Y)≠0なら、その差の精査を要求する**こと。

小さいライブラリからG(Y)を求め、保持された大きなsとの積や、元のsourceのkernelを展開せずに起点を作る。F、ε、語の終端の合否は、この関数へ渡さない。現在文脈では四候補とも非発火、後の文脈が到来すると三候補で発火した。

この規則は当該kernelの差を厳密に検出する。したがって、その限定された差があるかという問題は発火段階で解いている。ただし、それが指定した語の固定結果への成立を変えるか、調べる価値があるかは、まだ決めていない。曖昧な一般的「違和感検出器」が完成したとは解釈しない。

元のleaf応答・残差テンソル展開・閉鎖判定を呼べない状態でも発火できることを検査した。小さいライブラリのexact応答、regularチャートの照合、係数の非零判定、入力の束縛とハッシュは必要であり、検出コストが0という主張ではない。巨大な任意文脈でも常に安いという保証も置かない。

Yは保存済み実験から順に与える**模擬到来**。関数は渡された一文脈だけを読むが、実験者は元のデータを知っている。未知未来の予測試験、実際のLLM発火時間の測定、TE内部運動からこの起点規則を導出した試験とは区別する。Cに駆動や選択の力は足さない。

## 5. 発火と、その後の成立を別計算で比較する

三文脈×四sourceの12起点記録を保存してから、後段の比較を実行する。既存の二語を順序と途中の境界ごと保持し、元のsourceと代表sourceを比較する。実際の過去や在庫は書き換えず、試算側での介入である。

- 元の後文脈では、三source×二語の6件で発火し、代表への置換が固定結果の合否を変える。基準sourceの二語は双方で成立する。
- その文脈の対角成分を±1/1024ずらすregularな対照では、同じ6件で発火するが、元と代表は双方とも不成立になる。**差を検出したことと、このPで合否が変わることは異なる。** kernel差そのものに対する誤検出ではない。
- 係数差10⁻²⁰と10⁵⁰のprimitive対照でも、現在では非発火、到来文脈では発火する。差の大きさを発火閾値には使わない。これらを新しい認証済み上位作用としては数えない。

合計16対の語比較で、元のTE exact演算を後段の基準にする。元の各語のRR58区間判定も照合する。非発火側も全て検査して、結果がよかった例だけを残さない。保存した発火記録のdigestは後段でも一致する。digest単独は実時刻の証明や作者署名にはならない。

## 6. 検証と到達点

主8群、新12＋変更していないRR58の22＝34テストが通過。観測・入口・認証元・発火内容の差し替え、非発火の範囲外流用、発火記録を置換証やセル認証として渡す誤用、非可換な語と途中境界の保持を検査する。入力は信頼したRR57三記録をexact再実行・再出力で照合する。3+1の学習や128継続族は再生成しない。

**保持された差を全部展開する前に、限定した手がかりから精査の起点を作り、後から有効性を別に検査できた。** 今回新しく確かめたのは、この分離と、圧縮読み取りだけに頼る検出器の限界である。

起点規則は宣言した模型条件。一般的な棘、予測符号化、意味上の重要性、未知の未来に対する見逃し率、総計算量の削減、自己生成する注意機構の完成までは主張しない。次の課題は、現在の内部運動が生む観測からどの手がかりを作り、どこへ精査を配分するかを、発火前に固定して比較することである。
