# Time Engineの保持と置換の原則

2026-10-18。アキの指示により、以後の実装で守る基本原則として固定する。

**置換可能性は、差を保持したまま、指定された演算範囲でその展開を省略できる保証である。**

## 1. 判定と消去を分離する

置換可能と判定することは、残差を消去する許可を与えない。代表値を使って読出しを省略しても、元の作用・残差・認証・履歴は保持する。読出しの最適化が実際の完了記録を上書きしない。

## 2. 保証の範囲を記録する

判定証には、元の対象と代表、入口、許された後続の族Γ、保存対象P、境界と許容誤差を結びつける。同じ圧縮値、同じ現在応答、同じ成立判定、同じ実際の終点、同じ履歴は、それぞれ異なる保存対象である。

\[
a\sim_{\Gamma,P}b
\iff
\forall\gamma\in\Gamma,\quad P(\gamma[a])=P(\gamma[b]).
\]

この保証を、別の観測・入口・後続族へ自動で持ち越さない。元のΓに対する判定は保存し、新しい範囲には新しい保証を求める。

## 3. 未判定を保持する

判定は「指定範囲で置換可能」「指定範囲で置換不可能」「未判定」を区別する。予算内で差が見つからないことを置換可能と同一視しない。範囲を検査し切れなければ未判定として差を保持する。

## 4. 差の運ばれ方を保持する

代表値と未展開残差を、後続の作用を受けた結果まで再展開できる表現で保持する。元の差だけを保存し、以後を代表値だけで上書きする処理にはしない。

保持先を参照する形式では、元の完全な記録へ到達でき、そのハッシュを照合できることも必要である。参照先を失った状態を、差を保持した状態として扱わない。

接続則が境界テンソルや順序付き履歴を読むときは、その観測に対する保証が要る。ある文脈で作用値が同じという判定だけで、RR53の接続読出しまで代表へ差し替えることはできない。

## 5. 近似判定と実際の認証を分ける

粗い区間が同じ合否を保証する場合、候補の読出しを省略できる。保証できない場合は精度を上げるか、未判定を返す。実際のsource公開、階層の照合、Decoder認証、実際の終点と履歴は、その元の条件を保つ。予測用の判定証をセルの認証として使わない。

## 6. 自由数との対応

Free Numbers Coreの「Compression is not disappearance」に沿い、圧縮値と残差を別々に扱う。RR58では、凍結版CoreのB₂分解と内部応答を用いる。複合されたTEの作用は順序付きの式として保持し、一つのB₂テンソルへ潰さない。

全ての可能なprobeに対する完全な応答を保存する問題と、限定した演算範囲で展開を省略する問題を分ける。RR36の単射保存条件を、局所判定を理由に解除しない。
