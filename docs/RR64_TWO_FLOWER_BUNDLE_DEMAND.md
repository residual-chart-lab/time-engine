# RR64 — 二輪の終端要求を、最初の実行より前へ引き戻す

2026-10-21。RR63を基準に、修復済み自由数 runtime 0.1.1を採用した。

**二輪の出力をまとめる一つの未来要求から、最初の実行前に、現在候補の許容性と後続sourceの補正を求める。** 実行済みの成功経路を要求へ埋め込まず、実際の出口・既存在庫・下位での生成と公開を通して、二輪とその上位セルを閉じる。

未来因果をTEの設計前提として保持する。ここで強化するのは、その前提で使う具体的な演算則と実行上の保証である。

## 1. RR63から引き継ぎ、今回追加したもの

RR63は一輪を段階実行し、正常停止し、実際の出口を次輪へ渡す。ただし元のCについて次輪まで保証する作用則はなかった。

今回は、指定した二輪継続を一つの要求へ結ぶ。

```text
認証済みの過去・保持S
    ↓ 登録（入口認証は厳密）
独立に固定したC、現在候補(v, word)、二輪目の補正可能範囲
    ↓ 自由数の式と区間から、実行前に許容性・必要な精査を求める
必要なときだけ保持sを読み、二輪目の補正αを確定
    ↓ 現在が候補を選んで実行
第一輪 HHST / HHTS → 実際の出口をRR53で読む
    ↓ 同じ在庫・累積値・履歴を継承
第二輪 HR → 二つの実出力 O1, O2
    ↓ 単一のC、実際の継承値−1
上位セルが+1に初回閉鎖し、停止
```

元の完成済み3+1、RR53の出口読出し、既存の生成・認証・公開・Decoderを変更しない。新しい動力学的primitiveは足さない。追加したものは、二輪継続の指定、作用則、スコープ付き精査、実行と照合である。

初期登録は既に閉じたRR60の一輪を利用する。したがって今回の「二輪」は、**登録後に実行する二輪**を指す。記録内の総round数は3、在庫は5→6→7、上位出力数は1→2→3となる。過去の一輪を消して数え直してはいない。

## 2. 要求と自由を先に固定する

主入力は計算前の[コミット9f534b9](https://github.com/residual-chart-lab/time-engine/commit/9f534b9d1223c4ee4f6388363f1b4432d244f243)に保存した。

- Cの文脈は `diag(x,1−x,0)`。RR61/RR62の全14点を成功による選別なしで再使用。
- 保持・消去・復元の3履歴。現在の観測応答は一致する。
- 第一輪の語は `HHST`, `HHTS`。source `S` は元の公開済みsource、`T=X*+vΔ`。vの宣言範囲は[−64,64]、主検査は−64,0,64。
- 二輪目の語は `HR`。補正αの主範囲は[0,16]、狭い範囲[0,8]も比較。
- 各輪の現在要求は−1。二輪をまとめる上位要求は+1、継承値は実際の−1。
- 出口結合強度は1/1024。強度0を対照とする。
- 問いPは「二輪継続が存在するか」と「実行する後続作用」の二つ。

ここでいう境界・sourceは対称trace 1のaffine chartであり、正値行列には限定しない。Cは終端条件を与え、現在の語やvを一意に命じない。現在の6候補を調べることと、未来の完成経路を列挙することは別である。

固定入力の正本SHA-256は `1db157d7d6548905390766382ff4d69a8028500011ef758c6dd87a2014a19f77`。公開コミットの実バイトを読み戻して一致させ、計算開始時にも検査する。

## 3. 二輪の作用則

元の残差族を `S=X*+sΔ`、第一輪の新sourceを `T=X*+vΔ` とする。このchartではΔ=diag(−2,1,1)。保持sの厳密値は自由数Vaultに残す。

Hは二つのprimitive葉からなる。第一輪の語はprimitiveに展開すると6葉となり、既存RR53の位置重みは `1/21,...,6/21`。したがって、実際の第一輪出力からの文脈は

\[
Y_2=Y_H+\eta\{R_{ordered}(O_1)-I/3\}
   =\operatorname{diag}(y_0,y_1,y_2).
\]

自由数の読出しは、この式をsの多項式として構成する。元のsや、完成した未来のO1を判定のために先に生成しない。実行後には、実際の出口から得たY2と式が完全一致することを別に検査する。

TEでのprimitive応答は

\[
J_C(X)=\sum_{c,d} C_{cd}e_d A_2(X)(e_c),\qquad
J_C(X)=2\sum_i C_{ii}X_{ii}-1
\]

（後者は対角trace 1の場合）。圧縮されたm2だけへの読出しには置き換えない。

\[
h=H(Y_2)=(2y_0-1)(2y_1-1),\quad d_y=y_0-y_1.
\]

二輪目の補正は現在要求を変えない自由方向を使う。

\[
a=\frac{(1/h+1)/2-y_1}{d_y},\quad
R_0=\operatorname{diag}(a,1-a,0),
\]
\[
\Delta_2=\operatorname{diag}\left(
\frac{y_1-y_2}{d_y},\frac{y_2-y_0}{d_y},1\right),\quad
R=R_0+\alpha\Delta_2.
\]

`J_Y2(R)=1/h`なので、HRは実際の−1から再び−1へ閉じる。αは現在の閉鎖では見えないが、共通Cの下では一般に見える。

第一輪出力のCでの作用を

\[
B_1=H(C)^2J_C(S)J_C(T),\quad \kappa=-H(C)B_1
\]

と置くと、二輪の上位終点は

\[
q=\kappa\{J_C(R_0)+\alpha J_C(\Delta_2)\}.
\]

`C=diag(c0,c1,c2)`に対して

\[
A=(c_0-c_1)\{1+h(1-2y_1)\}+(2c_1-1)hd_y,
\]
\[
B=2\{c_0(y_1-y_2)+c_1(y_2-y_0)+c_2d_y\},
\]
\[
N=hd_y-\kappa A,\qquad D=\kappa hB.
\]

よってD≠0なら、**二輪を+1へ閉じる補正は実行前に `α=N/D` と求まる。** N,Dは保持sの有限多項式であり、自由数runtimeで混合項と相殺を保持して引き戻す。除算・chart・資源区間の検査はTE側に明示する。

これは指定した継続の必要十分な終点条件である。閉鎖認証まで含めるには、下記の初回境界・生成可能性の条件も必要になる。

## 4. 成立可否と精査、実行許可を分ける

登録時には過去の履歴と保持値を厳密に認証し、digestを一度計算して保持する。各照会で元の履歴全体を読み直して「保持差を読むべきか」を判定しない。

判定は保持sの認証済み区間を使う。分母が0を含まず、αの包含区間全体が資源範囲内なら、存在を厳密値なしで保証できる。区間全体が外なら、その範囲では不成立。境界をまたぐ場合や極を排除できない場合は精査へ回す。

実際にRを生成するには、作用の問いに対応してsを厳密に読み、αを確定する。存在判定証だけでは実行できない。どのケースも差を削除・代表値で上書きしない。

判定では少なくとも次を区別する。

- H(C)=0：非零の上位要求には届かず不成立。
- Cが既存認証chart外：未解決。数学的な不可能とは数えない。
- Y2の正則性、h≠0、hと1の分離、上位の第一出力がまだ終端でないこと：包含区間で確認し、必要なら精査。
- 下位sourceの活動性：退化候補を実行許可へ流さない。
- D=0等の退化：保証した空集合を除き未解決として残す。

現在の両語は実行時にも初回閉鎖を認証する。sourceは下位で実行して認証・公開した後だけ使用する。scopeには入口、C、v、語、結合強度、α範囲、問いP、固定要求、継承値を結び、差し替えた判定証や作用を拒否する。

## 5. 検証結果

主入力から計600照会。全件、別に行う厳密行列・affine補正計算と一致した。この対照も完成した未来経路は必要としないが、保持値を直接使う。

| 問い | 照会数 | 判定・解決段階の保持sの厳密読出し |
|---|---:|---:|
| 二輪継続の存在 | 300 | 0 |
| 実行する後続作用 | 300 | 168 |

入口認証、対照計算、実行、保存と再認証の厳密計算はこの省略件数に含めない。全処理の高速化率とはしない。

主実行行列はx=−1,1/4、v=64、保持・消去・復元、両語の12件を先に指定した。x=−1の6件が実行・二輪閉鎖・上位認証に成功。x=1/4の6件は指定したα範囲では不成立として保持し、別Cへ差し替えて成功件数を増やしていない。

同じ局所結果でも保持差は後続のRを変え、復元では元のRが戻る。消去側の補正を保持側へ流用する対照では、**両輪はそれぞれ−1に閉じても、共通上位要求+1に届かない。** 局所の閉鎖だけでは、束の成立を保存できない。

両語の違いは実際の出口文脈と必要補正へ届く。RR53の結合強度だけ0にすると語順による補正差は消えるが、元の履歴は残る。

主600照会の後に、第一候補の許容範囲を見やすくする**追加診断**を置いた。keep、x=−1、同じ6候補について、二輪目の補正上限を4,8,12,16とすると、許容候補数は0,0,4,6。上限12ではv=−64の両語が外れ、v=0,64の両語は残る。未来の完成経路を作らず、保持sの厳密読出しも0回で、この選別ができる。上限12・v=64・HHSTの一件は実際にも認証した。この診断を計算前に固定した主実験とは呼ばない。

主実行6件と追加診断1件、計7組が二輪・上位認証に成功。新22テストと、RR62・RR63・旧自由数読出し・環境間搬送の関連検査を実施する。件数・ハッシュの正本は [RR64-validation.json](../integrations/inquiry/RR64-validation.json)。

## 6. 保存と再現

要求と保持差のグラフに加え、実際の両輪・下位source・在庫・累積値・時系列・上位セルを一緒に保存する。読込時は外部で保持したSHA-256、元の入口とscopeを要求し、自由数グラフの一致と、元の要求からの厳密再実行で照合する。成功していない対照を完了記録にはできない。

修復済みruntimeの上限・非再帰処理・整数codecを自由数グラフに利用する。TEの既存graph codec全体まで任意深さに強化したとはしない。RR64の保存は完了した二輪の記録であり、二輪の任意の途中段階からの再開は今回追加していない。RR63の段階保存は基準版のまま保つ。

Python 3.10以降、標準ライブラリのみ。リポジトリ直下から：

```sh
python run_bundle.py choices --x=-1 --later-max=12
python run_bundle.py run --x=-1 --v=64 --word=HHST --out .work/bundle.json
python run_bundle.py verify --x=-1 --v=64 --word=HHST --record .work/bundle.json --sha256 <直前に返された値>
python integrations/inquiry/validate_bundle.py
```

`choices`は現在候補の表示だけで止まり、sourceを生成しない。`run`は選択した二輪と上位セルを実行し、閉鎖して停止する。既存の出力ファイルを上書きしない。検証出力は`.work/rr64-local/`。配布済みのRR64記録は書き換えない。

採用元：TE基準merge `d235252bd6630baa08068534cf898535e06036e8`、自由数merge `a9c3041a411db8f79f51d02e9f35af58f5edb2d3`、実装固定 `d3a70c78694748b0362568524cc8f9e2b875d87e`。基準269ファイルのうち案内文書2件だけ更新し、他267ファイルと自由数vendorをハッシュ照合する。

## 7. ここで確定した範囲

**束の未来要求が、どの保持差を通して、現在候補の許容性と後続の実作用を拘束するか**を、実行前の式・精査・実際の認証へつないだ。二輪目でできることを変えると、一輪目で許される候補が変わる。現在の複数の選択は残せる。

今回は対角source族、指定した両語とHR、既存RR53の読出し、明示した補正資源範囲についての作用則である。任意の非可換source・長さ不定の継続・自律的なC生成までは導出していない。主範囲[0,16]では成立Cの6候補がすべて残るため、常に選択肢が減るとはしない。

同じ情報と算術を与えれば前向きの制約計算でも同じ式を実装できる。そこをTEの設計前提を外す理由にはしない。現在側の局所結果だけで差を置換すると、二輪の成立を失う対照が今回の具体的な設計上の根拠である。
