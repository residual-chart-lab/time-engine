# RR69 — 固定した観測構成器を、三輪の要求へ渡す

2026-10-23。RR68固定版 `a189fc12382cdda3011c7b73c2e783821745a16c` からの追加。

**RR68の観測構成器と既定予算を変えず、異なる三輪の有理演算へ接続した。構成した観測から途中の文脈・作用・成立条件を再現し、実際の三輪と上位セルを閉じた。**

ここでの新しい成果は、三輪の存在そのものではない。要求の式から十分な観測を構成する部品を、二輪とは異なる要求式へ渡せたことである。

## 1. 固定した部品と、新しい入力側

`integrations/inquiry/observation_synthesis.py` のSHA-256は、RR68と同じ

`407250087436ae8abe5dd487d9a2e9334fb45070e379ddbc04b9c857f706d5e0`

である。次も固定した。

- 観測は最大2個、各観測は次数2以下。
- 入力多項式の次数は最大16、項数512、次数ごとの生成積数512。
- 入力は有理係数の多項式群と形式変数。観測候補や保持値は渡さない。
- 出力は観測の定義と全入力式の再構成恒等式、または予算内で未解決という結果。

今回追加したのは、三輪の演算をこの入力へ変換し、保証を実行まで運ぶ側である。RR68の二輪計画器を呼んで三輪の答えに置き換える方法ではない。既存の観測値の登録・由来照合・既読観測からの導出には、RR68の処理を再利用する。

基準版377ファイルのうち、案内用README二件を除く375ファイルを完全一致で保持する。完成した3+1、自由数Core/runtime、元のTE接続・認証処理も変更しない。

## 2. 今回の三輪

RR65の認証済み入口を使う。過去の二輪で実行されたsource S/Uと、保持座標 s/t はすでに同じ在庫・時系列にある。

新たに実行する語は次の三つ。

1. `HHHSUT` または `HHHUST`。Tの現在自由度 v は入力として選ぶ。
2. 最初の実際の出口をRR53の順序付き接続へ渡し、その文脈Y₂で `HR₂` を実行する。
3. 二輪目の実際の出口も同じ接続則へ渡し、その文脈Y₃で `HR₃` を実行する。

各輪は、継承値−1から固定結果−1へ厳密に閉じて停止する。作った作用は下位で実行・認証・公開してから使用する。在庫は6→7→8→9、各輪の実終点は−1のまま継承する。

最後に、この三つのlevel 3出力を、共通文脈Cで一つのlevel 4セルへ渡す。固定要求は、継承値−1から結果+1。途中の二つのprefixが先に+1へ閉じないことも確認する。

**これはRR54/57の近似根による枝をそのまま再実行した結果ではない。** RR65の厳密なsource族とRR53の接続則を三輪へ延長した、新しい要求の受け手である。旧RR54のsource分枝や校正済み上位文脈を、今回の定理の対象へ混ぜない。

## 3. 未来要求が拘束する式

対角source重み r と対角文脈 Y に対し、

\[
J_Y(r)=2\sum_i r_iY_i-1,\qquad h(Y)=(2Y_0-1)(2Y_1-1).
\]

現在の補正を満たす族を

\[
R(Y,a)=R_0(Y)+a\Delta(Y)
\]

と書く。R₀は第三成分0の現在補正、Δは現在応答を変えない既存の方向で、第三成分1である。従って

\[
h(Y)J_Y(R(Y,a))=1
\]

を保ったまま a を選べる。

今回、R₂=R(Y₂,u) のuも現在の入力として残す。Cはvやuに特定の経路名を指示しない。

三輪の共通Cでの作用値をB₁、B₂、B₃とし、h_CをCでのhead作用とすると、

\[
B_2=h_CJ_C(R_2),\qquad B_3=h_CJ_C(R_3),\qquad -B_1B_2B_3=1.
\]

これと三輪目の現在補正を同時に満たすため、

\[
\alpha=
\frac{-1/(h_CB_1B_2)-J_C(R_0(Y_3))}
 {2\sum_i C_i\Delta_i(Y_3)},\qquad
R_3=R(Y_3,\alpha)
\]

を実行前に求める。分母が非零で、元のchart・prefix・資源条件も満たす場合にだけ、この作用を許可する。

Cは成功経路から逆算していない。`main=(-1,2,0)` は固定入力、`mixed` は既存の基底sourceへの応答を0にする診断文脈である。後者は混合差を切り分けるための設計条件であり、完成した三輪から選んだ文脈ではない。

有限の現在候補について、許されたものはそのまま残す。今回の288計画のうち108は成立可能、108は指定族で不成立、72は未対応chartだった。語やuを一つに固定する未来選択器を追加したわけではない。

## 4. 有理演算の保証をどう渡したか

三輪では、R₂を作る割り算、そのR₂から作るY₃、さらにR₃の割り算が重なる。RR68の全13多項式を、そのまま新しい三輪の式だと呼ぶことはできない。

入力側は、既知の三輪の演算から、有理演算グラフを作る。加算・乗算・除算の順序を保持し、割り算を含まない部分を多項式としてまとめる。全作用・文脈・guard出力と、元の全除算の分母から到達する多項式群を、固定した構成器へ渡す。観測の候補名は与えない。

得た観測φについて、多項式部分すべての

\[
p_j(s,t)=\widehat p_j(\phi(s,t))
\]

を厳密に再展開して照合する。その後の加算・乗算・除算は、元と同じグラフで行う。

保証はグラフ順の帰納法でつながる。入力の多項式値が一致すれば、加算・乗算の出力も一致する。除算では分母値も一致するので、両方とも同じ場所で未定義になるか、両方とも定義されて同じ値になる。従って、文脈、R₂/R₃、prefix、資源範囲の判定も変わらない。

**分母を約分して消したり、0を掛けるから検査を捨てたりしない。** `s/s` や `0*(1/s)` は、s=0では許可されない。元の分母guardを独立に保持する検査を追加した。

ここで次数16の上限がかかるのは、構成器へ渡す多項式群である。三輪の有理式全体を一つに展開した次数が16以下、という主張ではない。これは構成器の予算を増やした結果ではなく、**有理演算グラフへ恒等式保証を合成する入力アダプタ**の追加である。グラフ自体にも1024ノードの上限を置く。今回の最大は191ノード、28多項式部分、入力次数2だった。

## 5. 出てきた観測と、実際の仕事

mixed文脈で最初の接続強度が0なら、今回の三輪の要求も積stの一観測で再現できた。座標をx=s+t、y=s−tへ変更すれば、構成器はx²−y²を取り出す。二輪目から三輪目への接続だけを非零にしても、最初の保持差を読む観測は一つで足りた。

最初の接続も非零とした成立候補では、順序付き接続が読む線形の組合せと、積が構成された。`HHHSUT` の元座標では、例えばs+(8/7)tとstになる。Cをmainに替えると、個別情報を復元できる二つの一次観測が必要になる場合もある。

既にRR68で取得した二輪用の観測値も、定義と由来が合えば三輪側へ再利用できた。元値の追加読出しなしで同じ三輪作用を復元する検査が通る。

初めて数値登録する場合の費用は残る。積一つの初回登録では、元のs/tを二回読み、観測を一回抽出する。合計三回を計上している。元の保持値や未使用の旧観測は保存し、今回の構成を全体の高速化とは呼ばない。

## 6. 保持・消去・復元と、閉じても成立しない対照

同じmixed C、同じ三輪要求、同じ現在選択v=1・u=0で比較した。

- 保持：三輪と上位セルが成立する。
- 片側消去、もう片側消去、両側消去：上位prefixの作用が0になり、この族では+1へ届かない。
- 復元：保持と同じ成立が戻る。

消去対照でも、最後の補正を局所条件だけで作れば、三輪それぞれは−1へ閉じる。しかし共通Cでの終点は0のままで、束は成立しない。この負対照は成功記録として発行しない。

保持した入口で現在選択v=0を試す別対照でも、三輪を局所的には閉じられるが、同じ上位要求は満たせない。実行前の則は、その候補を不成立として除外する。過去を巻き戻して、成功する履歴に置き換える処理ではない。

消去条件は、元の差を持つ実行と比較するための別の認証済み入口である。運用中に「置換可能」と判定したから元記録を消す機能は追加していない。

固定結果は `integrations/inquiry/RR69-*.json`、再計算先は `.work/rr69-local/`。今のモデルでCをどこから自律生成するか、運動途中で新しいCを受け取ること、任意の運動式での最小観測探索は今回の対象に含めない。

## 8. 動かす

Python 3.10以降、標準ライブラリのみ。

```sh
python run_three_synthesis.py inspect --context mixed --frame split
python run_three_synthesis.py demo --frame split --out-dir .work/three-synthesis-demo
python integrations/inquiry/validate_three_synthesis.py
```

`inspect`は新しい三輪の観測構成までで止まる。認証済み入口の用意には既存の過去生成が含まれるが、新たに要求された三輪は実行しない。`demo`は七段階を保存する。出力先は新しいディレクトリに限る。

`verify`には、保存した記録と外部で保持したSHA-256を渡す。初期文脈、両接続強度、座標、現在選択は作成時と同じものを指定する。

```sh
python run_three_synthesis.py verify --frame split --record .work/three-synthesis-demo/06-stopped.record.json --trusted-sha256 <外部で保持した値>
```
