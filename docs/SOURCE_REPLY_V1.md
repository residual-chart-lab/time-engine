# 出典付き返答の作用模型 v1

この追加は、会話の記録から次の返答・確認を実行する、Time Engineの有限な作用模型である。
未来要求Cを先に設定し、その要求を満たせる返答の組み立て方を、現在受け取っている原文から構成する。

**同じ現在の発言でも、保持した原文によって、次に実行できる返答が変わる。**

## 一件を動かす

~~~console
python -I -B examples/source-reply-first-use.py --output-dir source-reply-first-use
~~~

Python標準ライブラリで動く。出力先は、既存の親の下にある未使用ディレクトリにする。

既知の作例を使い、同じ要求を次の条件で調べる。

| 受け手へ渡す記録 | 出典条件を満たす返答候補 |
| --- | --- |
| 原文を保持 | 2通り |
| 訂正前の原文を外す | 0通り |
| 現在の結論部分だけ | 0通り |
| 今回の要求と無関係な後続発言だけを外す | 2通り |

どの条件でも、現在の応答を示す原文は同じ。
「今は何と答えているか」という要求なら、各条件とも同じ2通りの返答を組み立てられる。

例は候補数を比べて終わらない。

1. 保持側で、前後の引用と訂正箇所を添えた返答を実行する。
2. 訂正前を外した側で、不足原文を尋ねる質問を実行する。
3. 質問の後で保存し、プロセスを終了する。
4. 別プロセスで復元し、保管していた原文を外部から明示的に渡す。
5. 元の要求を再設定し、返答を実行する。
6. 最初の質問履歴が変わらず、得られた返答が保持側と完全一致することを確認する。

原文を尋ねた一手はそこで閉じるが、要求への回答は未成立のまま。
到来していない原文を推測して埋めない。

出力には実際の返答文、質問文、全命令・返答、復旧記録、結果表が残る。
これは固定したドライバーによる実行例であり、別AIの行動改善を測った試験ではない。

## 何を「成立」とするか

観測器の注釈を元に、会話の差をE1のs/tへ数値化しない。
新しい作用模型は、原文スロット・そのハッシュ・引用位置・入力された注釈を使う。

要求は二つに限定する。

- current_response：現在の応答として指定された引用を示す。
- retained_basis：保持されたという入力上の解釈を、訂正前・訂正後の原文と訂正箇所を添えて示す。

後者ではp=yesという注釈と、original_turnとして提出された前後の引用・訂正箇所が必要。
これらは**有限模型の条件**であり、意味的な連続性や本人の内的意図を証明する条件ではない。
返答本文にも、入力された解釈に基づく説明であることを残す。

機械が認証する範囲は、対象の原文が実際に渡され、ハッシュと引用位置が一致し、
固定した要求に必要な引用を備えた返答を実行したこと。
original_turnという分類や解釈の正しさは入力側の責任として区別する。

同じ根拠でも、引用を先に示すか説明を先に示すかを現在側が選べる。
読む・不足資料を尋ねる・未完了として待つ操作も残す。
未来要求は一つの経路を指定しない。

## 入力から返答まで

観測器と同じcase形式を使う。配布先AIは、原文と自分の注釈から入力を作る。
[AI向け手順](AI_SOURCE_REPLY_HANDOFF.md)も参照する。

まず、入力を固定した模型と受渡し用パケットに分ける。

~~~console
python -I -B run_source_reply.py compile --case my-case.json --output-dir reply-packets
~~~

出力は次の通り。

- retained.bundle.json：全原文を渡す。
- without-before.bundle.json：訂正前の原文を受け手に渡さない。
- current-only.bundle.json：現在の応答に当たる原文だけを渡す。
- blind-control.bundle.json：後続発言を外す対照。
- case.input.json：元の入力をそのまま保管する。
- CONTRACT.json / MANIFEST.json：作用則と各パケットの外部照合用SHA。

模型には原文本文や引用文を入れず、位置とハッシュなどを入れる。
受け手のプロセスに渡さなかった原文を、模型の中から読めるようにはしない。
比較時の原典は保管する。パケットの省略は、原典の消去許可ではない。
この作例は入力データの範囲を制限するもので、OS上の隔離やAIの記憶の遮断ではない。

操作系を起動する。

~~~console
python -I -B run_source_reply.py run --bundle reply-packets/retained.bundle.json --trusted-sha256 <MANIFESTのSHA>
~~~

以下を一行ずつ送る。次の命令は、前の返答を読んでから選ぶ。

~~~jsonl
{"op":"bind","requirement":{"target":"retained_basis","question":"この訂正で保持されたと解釈されている根拠を、前後の原文と訂正箇所を添えて示してください。"}}
~~~

返答のplansにはanswer / review / ask / deferがある。
admissible_answersは要求の出典条件を満たす返答候補だけ。
空でも、今後いっさい答えられないという意味ではない。
現在の受取範囲・注釈・この作用族で、すぐ成立させられる返答がないという意味。

~~~jsonl
{"op":"choose","plan":"<選んだplans内のid>"}
{"op":"resolve"}
{"op":"advance","permit":"<resolveで返ったpermit>"}
~~~

resolveは実際の引用を読み、検証する。advanceが返答・質問・読出しを実行し、
一つの応答をCLOSEDとして止める。出力のbodyが実際に組み立てた返答。
チャットへ自動投稿する機能はない。

certificate.contract_satisfiedは、返答の出典条件が成立したかを示す。
質問・読出し・待機でも一手は終わるが、この値はfalseになる。
自然言語の問い全体や主観的体験を完成した扱いにはしない。

要求や選択を変更すれば古い許可は失効する。
新しい要求をbindすると次の応答を始められるが、完了済みの応答履歴は残る。

## 資料の到来と再開

~~~json
{"op":"save","path":"new-checkpoint.json"}
~~~

保存は上書きしない。返答のSHAを外側で保管する。

~~~console
python -I -B run_source_reply.py run --bundle reply-packets/without-before.bundle.json --trusted-sha256 <パケットSHA> --resume new-checkpoint.json --trusted-resume-sha256 <保存時SHA>
~~~

模型で宣言済みだが受け取っていなかった原文は、到来した時点で追加できる。

~~~json
{"op":"supply","source":"before","text":"<実際に到来した原文>"}
~~~

原文のハッシュが凍結模型と一致する場合だけ受け取る。
既存の原文を上書きしない。完了した質問の後に資料が来た場合、
次のbindを行って新しい応答を選ぶ。

模型に存在しなかった新しい資料や注釈の訂正には、新しい模型が必要。
以前の完了記録を変更して整合させない。

span_readsとcached_spansは引用を確認した回数・保持数。
入口のハッシュ照合、E4の検証、復旧時の再演、総CPU時間の費用とは別。
全体の高速化を主張しない。

## E4との接続

この操作系は、受け取った模型・原文・要求・実際の操作・出力をE4へ記録する。
返答を実行する前に出典条件とE4の予算を照合し、どちらかが失敗すれば変更を確定しない。
保存・再開時は、資料の到来順も含めて実行とE4記録を再演し、一致を確かめる。
JSONオブジェクトのキー順は出来事の順序として扱わず、受取時に正準化する。
直接生成した束とファイルから読んだ束でも、同じ登録履歴になる。

E4の従来のE1数理実行器はUNBOUNDのまま。
今回の認証はsource-reply-v1作用族のものであり、四元数模型の認証とは区別する。
E4の原文・来歴の保持に、新しい作用族の実行器を接続した形である。
既存E1の係数を会話に都合よく読み替えたものではない。
この作用族は出典要求に合わせて新たに定義したもので、既存の四元数作用則から導出したものではない。
E4との接続と、新しい作用族内部の正しさを検証した段階である。

外部へ自動送信はしない。受け手AIは出力を読み、実際に使ったことを別に記録する。
自由に言い換えた文章まで、この返答証明書で認証されたことにはしない。

## 有限模型としての内容

観測器で検査済みのケースから構成した固定模型Mと要求Cから、必要な原文位置の組W_C(M)を構成する。
現在受け取った原文の集合をIとすると、成立する返答は

~~~text
A_C(I) = {(w, style) : w ∈ W_C(M), sources(w) ⊆ I}
~~~

となる。原文本文は凍結ハッシュと一致するものに限る。
構成器はこの条件を満たす組を作り、終端検査器は実際の原文を読み直して条件を検査する。
したがって、この作用族では上の包含条件が、出典付き返答を構成できる必要十分条件になる。

現在の応答を示す要求では、afterだけが必要になる。
保持根拠を前後から示す要求では、beforeとcorrectionも必要になる。
この違いが、省略した差を実行前に必要とするかを分ける。

数学的には、通常の前向きの出典検査・有限制約充足としても同じ許容集合を表現できる。
TEの設計では、未来に満たす要求を現在の作用構成へ結合し、
その範囲で置換できない差を実行へ運ぶ。

原文の全引用が有効でも、意味の判断自体が誤っている可能性は残る。
また、別の操作・資料探索・未定義のLLM応答まで不可能とする定理ではない。

新16検査で、独立な参照実装による全16原文部分集合×2要求＝32範囲を照合する。
同じ現在、後続成立の分離、無関係な差の対照、復元、未知、
資料到来、履歴不変、許可流用拒否、改変拒否、予算失敗時の復旧、
通常操作口による実行を確認する。

~~~console
python -I -B -c "import sys,unittest;sys.path.insert(0,'integrations/inquiry');r=unittest.TextTestRunner(verbosity=2).run(unittest.defaultTestLoader.loadTestsFromName('test_source_reply'));sys.exit(not r.wasSuccessful())"
~~~

既知の作例による開発・実行検証である。
次の試用では配布先AIが未使用の会話一件を選び、要求を先に固定し、
自分で選んだ操作と実際に使った返答を残す。
その結果で、自然言語の理解や行動の改善まで一般化しない。

入口は256KB、原文は8スロット・合計12,000文字まで。
操作は32命令、1命令64KB、復旧記録2MBまで。
E4の既存上限も適用する。予算が足りない操作は確定せず、
直前の状態を保存・復元できる。
