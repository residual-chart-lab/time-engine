# 2026-10-19 — 搬送検査の準備と、ローカル再現の対照を修正

**公開記録の搬送検査は公開値に束縛し、1 ULP差の再現検査は同じ環境で生成した記録を基準にする。** 修正対象はテストの入力準備。搬送API、3+1、TEの作用・閉鎖・履歴は変更しない。

## 1. 監査で分かったこと

[ユーザー提供の監査原文](../integrations/three_plus_one/astra-audit-2026-10-19-user-supplied.md)によれば、RR57の主11群・新16テストと128継続、RR58の36テスト・22読出し、RR59の34テストと保存結果が別環境で再現した。公開3記録の搬送・exact再実行も通った。

一方、`test_portability.py`の`setUpClass`は、公開記録を既定の`reproduce`で読み込んでいた。公開値と監査環境のbinary64出力が異なると、全10テストが準備段階で止まった。さらに、1 ULPを加える二検査も公開記録を基準にしていたため、元からある環境差と注入した差を混同し得た。

過去の78件PASSは当時のこちらの環境での実行記録として保存する。監査時点の未修正検査一式を、別環境でも全件PASSしたとは扱わない。搬送処理が通ることと、テスト一式が起動することを分ける。

## 2. 修正

- 公開記録の準備は、固定したマニフェストの設定・mode・境界・自由選択値・外部の信頼したSHA-256を使う`transport`へ統一した。公開境界をローカルに作り直さない。
- 1 ULPの二検査は、その環境で実行・保存した記録を使う。差を注入する前に、既定の再現読込と再出力が無変更の記録へ一致することを確認する。その後で1 ULP差の拒否と、自動搬送への切替が起きないことを検査する。
- 準備処理だけを、上流の学習・ローカル入口・境界生成を禁止した状態で呼ぶ回帰検査を一つ追加した。公開記録の準備がこれらへ依存すると失敗する。

準備をスキップしたり、誤差を許容して記録を同一視したりする修正ではない。元の公開記録とハッシュ、既存の拒否条件を保つ。

## 3. 検証の範囲

RR56の既存ドライバーで主9群と全79テストを実行する。内訳は搬送11（元の10＋準備の回帰1）と関連68。公開3記録の搬送・再出力、同環境で生成した3結合記録の実行・保存復元も含む。配布物を別展開した検証では搬送11件を実行する。

保存版の根拠は`integrations/three_plus_one/portability-test-fix-2026-10-19-validation.json`と同名の`.log`。従来のRR56〜59の結果、原典131件、3+1 vendor17件、元の六完了記録はそのまま保持する。

## 4. 再現

搬送11件だけを実行する：

```text
python -m unittest discover -s integrations/three_plus_one -p "test_portability.py"
```

主9群・関連を含む79件と、結合記録の生成・照合を実行する：

```text

```

公開済み記録の搬送だけなら：

```text
python integrations/three_plus_one/validate.py --transport-only
```
