# 何を守ったのか — 保護対象を分けて問う

2026-10-25。P0と監査済みE3の外側に置く、追加の読み取り専用診断。

> 卵の殻を守ることと、卵の中で育っているものを守ることは、同じではない。

この言葉を、TEでは**守る対象Pを明示し、別の対象の保存と混ぜない**という原則へ落とす。「亀裂」は問いが始まる契機であり、それだけで損傷や誕生を確定するラベルにはしない。

## 今回組み込む区別

| 対象 | この有限模型で計算するもの |
|---|---|
| 現在の読み取り | 現在の継承文脈で、指定した第一語を作用させた終点 |
| 指定した後続の成立 | 同じ現在選択と三輪要求の下で生成されるT/R₂/R₃、またはその候補族の不成立 |
| 元の保持状態・履歴 | 診断によって変更しない。差の射影は試算側だけで行う |

現在の読み取りは終点という観測であり、それだけで最初の非空セルの認証まで保証するものではない。後続の比較も、固定したv・u・語と三輪の要求についてのもの。任意の未来や全候補の探索結果ではない。

新しい診断は、元の保持座標s/tを厳密に二回読み、指定した差だけを0へ置く仮想側を計算する。既存RR69の要求式・分母・chart・資源・途中境界の条件をそのまま使う。これは精査の費用を省くフィルターではなく、保護対象の取り違えを具体的に確かめる診断である。

## 出た比較

同じmixed文脈、両接続強度0、v=1、u=0、語HHHSUTで、一方の保持差sを試算側だけ0へ置く。

| 観測 | 元の保持状態 | sを0にした試算側 |
|---|---|---|
| 現在の第一語の終点 | −1 | −1 |
| 指定した三輪要求 | ADMISSIBLE | EMPTY |

「現在の終点を守れた」は成立しても、「指定した後続の成立可能性を守れた」は成立しない。片方t、または両方を試算側で0へ置く場合も同じ区別が出る。元のアーカイブと実際の履歴は変えない。

独立な行列・連立方程式の計算とも照合する。さらに既存の実行器で、保持時には三輪と上位が成立し、消去条件の開ループ対照では三輪の局所終点が全て−1でも上位は0に留まることを確かめる。負の対照を成功記録として発行しない。

この証人は既存RR69の現象を二つの保護対象から読んだもの。新しい生物模型や、殻を破る行為一般の正当化ではない。「形を変えて成立を守る」運動を自動選択する機構も、この診断では追加していない。

## 使う

この追加コードのあるcheckoutで実行する。固定P0 ZIPには含まれない。

```text
python -I run_preservation_check.py --entry integrations/inquiry/E1-entry.record.json --trusted-sha256 d71a430cf049b645dd44d6ebfd9870acfe00ed2b3ac54d1b5766641fa1f805a3 --expected-entry-digest 24ccd25412e46f5051ee5e48325358f8f62a66ce1244b69ce65fa57abce6f5de --omit s
```

`--context`、二つの`--strengths`、`--frame`、`--domain`、`--v`、`--u`、`--word`は、既存E2/RR69の範囲を使う。`--omit s t`なら二差の試算になる。任意のC・接続則・source族を追加する入口ではない。

出力はentry・scope・現在選択へ結びつけ、現在終点と後続作用の比較を別項目にする。

| `requested.relation` | 意味 |
|---|---|
| `DIFFERENT_EXISTENCE` | 片方だけ指定候補に許された後続がある |
| `DIFFERENT_NEW_ACTION` | 両方に後続があるが、新T/R₂/R₃が異なる |
| `SAME_NEW_ACTION` | この比較で新T/R₂/R₃が一致する |
| `SAME_EMPTY` | 両方とも指定候補では不成立。成功や保護の達成には数えない |
| `UNDETERMINED` | chart外・予算内で未解決など。一致や不可能性へ丸めない |

一致はこの一比較についての結果で、同じ圧縮値を持つ全状態についての保証ではない。作用のdigestは全係数を使った比較の識別用であり、作者署名や実行許可ではない。

通常の`run_time_engine.py`へ新しい操作を追加したわけではない。読み取り専用の診断口として呼び、元の実行器が発行する許可と区別する。`erasure_authorized`と`execution_authorized`はfalseであり、返答を書き換えても通常操作口はそれを許可として使わない。

## 検証と境界

```text
python -I integrations/inquiry/validate_preservation_targets.py
```

対象を分けた診断、元の完全記録の維持、独立な計算との一致、既存Decoderでの実行対照、両方不成立、chart外、差が0の対照、入力と実行許可の混同拒否、実CLIを確認する。元の除算条件に関する既存検査も二件再利用する。

結果は[検証記録](../integrations/inquiry/PRESERVATION-validation.json)と[ログ](../integrations/inquiry/PRESERVATION-validation.log)。これは新しい追加診断の検証であり、E3独立監査に含めたとは扱わない。生命の検出、LLM内部の棘の測定、自律的に保護目標を発見する機構、普遍的な未来因果の証明は追加していない。
