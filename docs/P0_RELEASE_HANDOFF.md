## 配布の正本

公開時の正本は、このTime Engineリポジトリの固定GitHub Releaseとする案。現時点のReleasesは0件で、ZIPの公開ダウンロードURLは未発行。存在しないURLを起動案内や告知へ載せない。

配布する模型は監査済みP0。E3をZIPの中身へ混ぜない。

| 受渡すファイル | 役割 |
|---|---|
| `time-engine-p0.zip` | 元の監査済みP0と全バイト一致する配布物 |
| `time-engine-p0.zip.sha256` | ZIP実体を照合する期待SHA。ファイル名とともに保存 |
| `time-engine-p0-acceptance.json` | 固定元、ZIP、監査、初見受入、E3との区別を記録する外側の補足 |
| `time-engine-p0-start-here.md` | 受け取ったAIが、照合・起動手順・自由数の案内へ進む短い入口 |

## 使う入口と、調べる入口

- **動かす**：[P0起動・保存再開](P0_STARTUP.md)。まず配布物の照合を行い、通常のJSON-lines操作口から使う。
- **調べる・疑う・改造する**：[自由数への読書案内](FREE_NUMBERS_READING_PATH.md)。Coreの固定原典・runtime・TEの採用範囲・検査・独立監査へ辿れる。

原典の通読を起動の条件にしない。受入試験の完走を原典へ進む条件にもしない。P0の操作成功から、自由数の説明がAIの検査行動を変えたと結論しない。

## E3の受入範囲

[Astraの固定監査](https://github.com/residual-chart-lab/time-engine/blob/0dd5e8b71cc094a69c50a8d8c6899581789d505e/research/astra-e3-audit-2026-10-24/REVIEW.md)で、`ccc0b93840e207ce9c3b2630acdf359a66bc2b54`のE3実装と読書案内はPASS。Linuxで14テストが通過した。既存P0の全監査は繰り返していない。

[監査受入の記録](../integrations/inquiry/E3-ASTRA-ACCEPTED.json)。E3は表示層の補修を含む別の成果。P0の直接Python APIで返答の入れ子を編集すると内部参照へ触れる点は、E3で補修されている。P0の通常配布手順は、JSONへ変換して応答するJSON-lines経路を使う。E3入りの配布物を作る場合は、別名・固定元・SHAを付けて新候補として受入を行う。

監査で指摘された版指定なしのP0構築手順は、P0受入状況と旧候補紹介で修正した。今回は文書と受入記録のみの補修で、作用・認証・保持・保存形式は変更していない。

## 今回確認したこと

監査済みP0展開物のbuilderから新しい出力先へ再構築し、ログだけでなくZIP実体を元の固定ZIPへ全バイト照合した。サイズ・SHA・CRC・manifestの429ファイルも一致。元のZIPは保持した。数理の全検査や初見AI受入は繰り返していない。

P0監査の初回再構築で観測されたログと後刻の実体の不一致は、原因未特定の記録として残す。今回の一致をもって、過去の不一致の原因が解決したとはしない。

公開直前には、用意したファイルと公開先の実体を照合する。Release、サイト、記事のURLが未発行の間は、公開済みとして扱わない。
