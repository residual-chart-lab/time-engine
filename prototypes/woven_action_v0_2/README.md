# 織られた経路を、次の作用へ — 試作 v0.2

2026-10-30。E4／recollectionと既存`source-reply-v1`作用族を接続する、実験用の外側の層。

**同じ現在の返答でも、辿って渡した原文が違えば、次に構成できる返答が変わる。足りない原文を求め、届いた後で選び直すところまで実行する。**

v0.1では経路から原文を読んだ。今回は、その読出しだけを受け手の作用系へ渡し、選択・精査・実行・原文到来・再選択を、既存の作用則でつないだ。数理核・P0・既存E4・recollection・source-replyのコードは変更していない。

## 結果

正式な再現記録は[evidence-v02/RESULT.json](evidence-v02/RESULT.json)。

| 段階 | 保持経路の受け手 | 省略経路の受け手 |
|---|---|---|
| 現在の発言を示す | 返答を実行 | 同じ本文の返答を実行 |
| 同じ後続要求：保持された根拠を原文で示す | 返答候補2 | 返答候補0 |
| 現在が選んだ操作 | 根拠付き返答を実行 | 訂正前の原文を求める操作を実行 |
| 求めた原文が到来 | — | 返答候補2へ変化 |
| 選び直した操作 | — | 保持側と同じ根拠付き返答を実行 |

候補2件は、同じ根拠を示す二つの表示順。一般のLLM返答全体を数えたものではない。

原文の到来を、二つの固定された窓で比較した。

- 「訂正後も保持された根拠を示す」C：候補集合が変わる。**この窓では境界を通過。**
- 「現在の発言を示す」C：候補集合は同じ。**この窓では境界を通過しない。**

後者は同じ状態変化を読む診断であり、そのCへの追加の実行許可ではない。[境界の計算記録](evidence-v02/boundary-witness.json)

原文要求をした履歴、以前の返答、以前の時点の読みを保持したまま、保存・復元が通った。新規16検査が全通過した。[検査ログ](TESTS.txt)

保持側・要求直後・返答後の3保存点を、最終コードでも検証復元した。[照合結果](RESTORE_CHECK.json)

## 何を新しくつないだか

既存PR #15の作用族を再利用している。原文不足で返答候補がなくなる法則自体を、新発見としては扱わない。

今回加えたのは、次の接続である。

1. E4のC別経路 → 歴史時点のticket → 実際の原文読出し。
2. 読み取った原文 → 明示されたsource slot → 既存作用系の受入パケット。
3. 実行前後の候補集合 → C別の境界検出。
4. 実際の要求・原文到来・返答 → E4の新しい通過経路への追記。
5. 両方の状態と境界の証拠 → 一つの保存点として保存・検証復元。

本文をキーワードやハッシュでE1のs/tに変換していない。受け手への原文はE4から実際に読んだもの。要求・出典・解釈注釈の対応は固定して明示する。

## 次の確認へ渡せる状態

今回の操作選択は、固定ドライバーによる。**別AIが未知の事例で、自分の判断を変えたことまで検証した結果ではない。**
