## v1で動くもの

一輪で選択・実行・認証・差の保持・停止を行い、その実際の出口を次の輪へ継承する。構成は**同階層の三輪＋上位の一輪**。一輪の完了と停止は正常な運動単位である。

指定した64経路の比較では、局所では成立する一輪目の4候補が、共通上位未来要求の下で1候補へ絞られる。除外された各候補は、指定した後続16通りでも成立しない。共通未来文脈を替える対照では、残る候補も変わる。

選択の確定後は再探索せずに実行し、三出力で上位セルを閉じる。実際の有理数終点を要求値へ丸めず、入れ子の履歴と二つの完全な完了記録を保存する。

**未来要求は通過可能性を定め、現在が選択する。** Cに選択や駆動の役割を追加しない。

上位未来文脈は明示した可解fixtureであり、候補照合には有限列挙を使う。独立した未来供給原理・任意経路への一般化・輪数一般の単調な拘束強化は未導出。未来因果は研究の中心仮説として保持し、模型で確認した作用と一般的な真理の証明を区別する。

## Cから必要な精査と現在の実作用をつなぐ：RR62

同じCでも、成立可否だけを問う84件は保持差の厳密値を読まずに答え、実行する作用を特定する84件では48件を精査した。全168件が元の厳密応答による対照と一致した。省略の範囲は判定・解決段階であり、入口認証と実行の厳密照合は別に行う。

元の保持sourceを実際の語へ再使用し、新しく生成するsource自体も保持差によって変わる。二つの語が同じ現在と未来へ閉じても、次の接続読出しには順序差が残る。計34実行・33成功。Cと問いPから必要な精査を起こし、実際のsource生成・公開・閉鎖までつないだ。[条件・証明・結果](docs/RR62_DEMAND_DIRECTED_RESIDUE.md)。

```sh
python integrations/inquiry/validate_demand.py
```

## 独立Cから現在の作用則を求める：RR61

成功経路から構成しない未来要求を先にコミットし、現在の観測が同じで保持履歴が異なる三状態に接触させる。完成経路の列挙を使わず、実行前に現在補正と自由な語族を求める。42判定、38実行のうち36件で未来のexact認証を得た。残りも不成立・未認証として記録する。

**この宣言した模型では、同じ情報を持つ前向き到達可能性計算と数学的に等価。** 独立した未来因果の追加原理やTEだけの計算的性質を証明したとはしない。保持差が補正へ効く作用則と、その適用範囲を確定した。[条件・証明・対照](docs/RR61_INDEPENDENT_C_PULLBACK.md)。

```sh

```

## 内部の接続要求から精査を起こす：RR60

## 精査の起点を調べる：RR59

現在の圧縮値と現在応答が同じでも、後の文脈で差が効くかは分かれる。保持された差を読む手がかりとして、既知の残差方向が到来文脈に露出したときに精査を促す規則を試した。発火と、指定した固定結果の合否が変わることを別に検査する。

主8群、新12＋RR58の22＝34テスト。これは宣言した一方向の族での読出し実験であり、LLM内部の棘や予測符号化の同定、未知未来の見逃し率、全体の高速化は検証していない。実際のsource・履歴・閉鎖認証は保つ。[条件・結果](docs/RR59_INQUIRY_INITIATION.md)。

## 自由数による保持と置換：RR58

**置換可能性は、差を保持したまま、指定された演算範囲でその展開を省略できる保証である。** 現在の応答が同じでも、後の文脈や接続読出しへの保証は別に求める。元の作用と履歴を代表値で上書きしない。

自由数Core v1のB₂分解を使い、現在では展開を省略でき、後の文脈では保持した差が再び効くことを確認した。保存された一輪・三輪から作る22件の読出しでは、元の厳密演算と合否が一致。20件は二進小数部48ビット、2件は80ビットの外向き区間で確定した。この応答評価でのexact leaf展開は基準126回に対して0回。入力照合・小さいライブラリの計算・実際のセル認証は別に必要である。

```sh
python integrations/free_numbers/validate.py
```

主10群、新22＋関連14＝36テスト。RR57の128継続族全体を再列挙した検証やTE全体の高速化率としては数えない。[条件・根拠](docs/RR58_DEFERRED_RESIDUE.md)。

## 3+1を内蔵したTEの強化：RR57

第一輪の現在位相と現在補正応答を保ち、局所では四接触×二語の全8候補が同じ−1へexactに閉じる条件を置く。完了した差を既存の接続で第二・第三輪へ渡し、共通上位要求を加えると、保持時には第一輪の00・短語、消去時には四接触の短語が残る。復元と結合強度0の対照、別の共通未来文脈も比較する。

各第一候補に後続16通り、介入ごとに128経路を照合する。これは完成した3+1を再設計する工程ではなく、第一輪に内蔵した保持差がTEの三輪全体で働くことの検査。00校正付き写像、可解fixture、有限の継続族という条件は明示する。

```sh
python integrations/three_plus_one/validate_three_flower.py
```

新主計算11群、既存RR56の9群、新16＋関連119＝135テスト。三つの完全な実行記録を保存・復元する。[条件と結果](docs/RR57_EMBEDDED_THREE_FLOWER.md)。

135件はRR57固定版の実行記録。2026-10-19に共通の搬送回帰検査を1件追加したため、現行の三輪ドライバーの構成は136件になる。今回、その三輪ドライバー全体を再実行したとは数えない。

## RR56の保存・再認証の補修

2026-10-19の監査で、公開記録をローカル再現で読むテスト準備の問題を修正した。公開値はハッシュに束縛した搬送で読み、1 ULP対照には同環境の記録を使う。準備の回帰1件を追加し、現在の範囲は搬送11＋関連68＝79テスト。[検査準備の修正と検証](docs/RR56_PORTABILITY_TEST_FIX.md)。以下の78件は初回補修時の記録である。

Astraの別環境でも往路の主9群・68テストは再現したが、配布記録の旧読込は上流の浮動小数の微小差で拒否された。公開済みの記録を信頼したSHA-256へ照合して読み、元の値を変えずに受け渡しとTEの有理数計算を再検証する搬送経路を追加した。

```sh
python integrations/three_plus_one/validate.py --transport-only
```

上流SGD・J・Kはこの搬送経路で再計算しない。ローカルな完全再現は別の検査として残し、別環境での一致は保証しない。補修の新10検査を含め計78テスト。原典131件、vendor17件、元の三記録は不変。数値再実行の出力は`.work/rr56-local/`へ書く。[保証範囲と検証](docs/RR56_PORTABILITY_REPAIR.md)。

## 3+1との最初の接続：RR56

3+1の17パラメータ基準ネットワークと四成分の局所運動を保ち、経験で生じた非一様な応答差をTEのsource係数へ渡す。現在の位相と現在補正応答を保ち、同じ未来文脈・F・εの下で、保持時は一接触、消去時は四接触が許される。復元で戻り、同ノルムの盲方向では四接触が残る。

00接触を基準に校正した部分チャネルであり、この接続則の必然性や二模型の同値性は主張しない。消去時の四接触は同じTE係数へ写るが、3+1の実更新はそれぞれ異なる。RR46・52のsourceごとの未来文脈再生成と区別し、共有の固定C受け取り口として検査する。

初版では主計算9群、新23＋関連45＝68テスト。三つの完全な結合記録で、実際の接触更新、sourceの実行・認証・公開、一輪の閉鎖・保存復元を確認した。教師値とCは役割を分ける。その写像を使った三輪での検査はRR57へ進めた。

```sh
python integrations/three_plus_one/validate.py
```

[実行方法・検証記録](integrations/three_plus_one/README.md) ／ [数理と接続条件](docs/RR56_THREE_PLUS_ONE_OUTBOUND.md)。基準版の原典131ファイルは不変。

## 開発の境界

- `baseline/v1/`：RR55統合文書13件とRR54実装・検証118件の固定保存。変更は新しい版または作業場所で行う。
- `docs/`：移行の来歴、接続結果と次の課題。
- `migration/`：131ファイルの対応表と今回の照合結果。
- `integrations/three_plus_one/`：内蔵部品の固定C接続と、RR57の三輪拘束、検査、完全な結合記録。
- `vendor/three-plus-one/`：指定基準版から変更せず固定した17ファイルとMITライセンス。来歴は`SOURCE.json`。
